# ⑧ 验证 · 怎么判「规范被实现了」

> 本篇定义验证体系：判据分类、期望值来源、工具、执行分频、失败处置。**期望值只准来自②–⑦，拿实现自己的输出当期望即自证，无效**（纲领·验证依据设计）。
>
> 实现转录：`tools/verify.mjs`（结构断言+截图）+ `tools/probe.mjs`（真值测量）+ `tools/probes/<页>.mjs`（断言集）+ `docs/test-cases.html`（用例总账）。

---

## 1. 判据原则

1. **可判定**：每条验证必须能判「过 / 不过」；判不了的表述不成规则。
2. **期望来自规范**：几何真值对③④，时间轴对⑥，文本对⑤，事实对②。
3. **报错显形**：任何断言失败必须回显原因；禁止静默跳过、禁止 `2>/dev/null`。

## 2. 断言体系（五类）

| # | 类别 | 判什么 | 期望值出处 | 失败表现 |
|---|---|---|---|---|
| 1 | 时间轴闭合 | 解说每行 结束≥开始；每步末行结束=步末；全片末行=总时长；词表外动作即抛 | ⑤词表 + ⑥相序列 | 运行时抛 Error，verify problems 回显 |
| 2 | 结构断言 | 挂载成功、编译产物完整、齿轮行与⑥目录一致、解说行结构与⑤一致 | ⑥ + ⑤ | verify 退出码非 0（注意：挂载超时是静默的，`dur=null` 冒充通过——看 dur 是否为 null 识破） |
| 3 | 几何真值 | 关键几何（卡位、槽位、包路径、弹跳缩放、线态）在指定时刻的实测值 | ③④ | probe 实测 vs 规范值超差 |
| 4 | 观感截图 | 四类基准帧的层次节奏人工判读 | ③④⑥ | 与基准帧偏差 |
| 5 | 覆盖率审计 | 源码无 `|| 字面量` 兜底、无色板字面量副本、无表外词、无相目录外行名 | ④⑤⑥ | 扫描命中即败 |

## 3. 工具与命令

| 命令 | 用途 | 耗时 |
|---|---|---|
| `node tools/verify.mjs <页> --no-shot` | 结构断言（1/2/5 类），报错回显；退出码非 0 即失败 | 单页 5–15s，全量约 2min |
| `node tools/verify.mjs <页…>`（去 `--no-shot`） | 加截图比对（4 类） | 11 页 3–4min |
| `node tools/probe.mjs <页> <scrub>:"(()=>{…})()"` | 写断言前量真值（scrub 是 0–1000 刻度） | 十几秒 |

- 环境：唯一 dev 依赖 playwright-core；浏览器路径特殊时 `CV_CHROME` / `CV_PLAYWRIGHT_CORE`；server 和 Chrome 必须同一条命令启动（拆开 = 每次冷启动）。
- 端口：remote-debugging 固定 9333；verify 内置端口管理可一次多页；手写 probe 一次一页。
- `Runtime.evaluate` 必须 `returnByValue: true`；`curl` 要 `--noproxy '*'`。
- **截图回显强制**：必须打印 `location.href` 与 `document.title`——端口写错加静默 = 命令成功、图是错误页。

## 4. 执行分频

| 时机 | 跑什么 |
|---|---|
| 每次改完 | verify 改到的页 `--no-shot`；**改公共层例外**：8 原语页全量 + 受影响规范页 |
| 提交前 / 每日定时 | 去掉 `--no-shot`（截图比对 + 人工观感） |
| 写断言前 | probe 量全部关键几何，再落成 `tools/probes/<页>.mjs`（与页面同名自动配对） |

## 5. 几何断言写法（防呆规约）

1. **先量后写**：写断言前读 paint 初值，不从路由和步骤反推。
2. **scrub 换算**：飞行中点用页面 `getCh()` 现算，不手算；段边界是动画起点不是中点。
3. **细扫小窗口**：固定大步长会漏小窗口相（如计算框只在合并段亮）；按⑥相键定位相中点采样。
4. **共用时间轴扫描**：同页多条断言共用一次扫描，不各自 seek。
5. **CSS 过渡帧**：`@delay` ≥ 800ms、终态给足 1200ms，否则截到 fill/opacity 中间态。
6. **两帧字节完全相同 = 必是废帧**，立刻查。

## 6. 截图四类基准帧

| 帧 | 时刻 | 看什么 |
|---|---|---|
| 初始 | `0@900` | 画面前提、灰线态 |
| 飞行中点 | 按⑥相键现算 | 包/残影/点亮中间态 |
| 终态 | `1000@1200` | post 态对②、余辉 done 态 |
| 窄屏 | 420×820 | `nr*` 骨架换轨 |

先截最可能出问题的 1 帧，不一次截五帧逐张读；几何一律用数字量，截图只看颜色层次节奏。

## 7. 失败处置与台账

1. 任何缺陷（验证红、人工发现、文档冲突）一律记 `docs/bugs.md`，**只记账不散落在聊天里**；每日定时巡检只记账不改码。
2. 红了的当场修；回归没跑不算完（公共层一改 8 页几何全变）。
3. 文档与实测冲突：收编期内以实测为准并**立即回改文档**（①§6.3）；收编完成后反过来，以文档为准改代码。

## 8. 与用例总账的关系

`docs/test-cases.html` 是本篇断言体系的**实例账**（编号、分组、分频标记），只在能判「过/不过」的验证动作占编号。本篇改判据先改本篇，再同步总账与分频表。

## 9. 终极用例 · 复刻测试

定期（或规范大改后）执行：以「只读②–⑦、不读代码」的视角走查一遍复刻流程。**卡住的每一步 = 缺规范条款**，记台账并回填对应篇。此测试是①§7 完整性判据的执行手段。

## 10. 时间预算（防返工螺旋）

新原语页 20–25 分钟；公共层改动回归 +10；每次返工 +8。**超预算就是在返工**——停下来重新想，别接着截图。
