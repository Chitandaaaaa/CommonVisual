# 规范三件套（草案）

> 状态：**草案，未入册**。修订流程同《设计铁律》：用户逐条改，定稿后分发进在册规范，本文件退役（去向记 specs.html 变更日志）。

## 0 · 制度：每份规范提供三件套

specs.html 01 章在册的每份规范，必须提供三件套，顺序与段名固定：

| 段 | 管什么 | 硬要求 |
|---|---|---|
| ① 定位 | 这份规范是什么——管什么、不管什么 | 1–2 句；只写抽象层，不写历史、不写具体数值 |
| ② 提供 | 这份规范给出哪些实物 | 只列可数实物（图 / 表 / 条目 / 参数 / 词表），数字必须与实物一致 |
| ③ 遵守 | 改动或新增这份规范管的东西之前，必须做什么 | 只写正向可判定条款，一条一件事；**冻结段** |

### 制度规则（冻结——只有用户明示才能增删改）

1. 每份在册规范三件套齐全；缺任何一段即规范不合格。
2. ①只写抽象定位，与实现细节、历史沿革分离。
3. ②随实现演进同步更新：改动落在哪份规范，就核对哪份的②，数字以实物为准。
4. ③冻结：实现怎么演进都不动，只有用户明示才改。
5. 三件套住在规范自己家里；specs.html 01 章保持一句话索引，不存第二份。
