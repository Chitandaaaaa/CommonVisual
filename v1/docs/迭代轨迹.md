### 第二版：精简动态演示页（深色）

**用户反馈**：完整版信息量太大、不够简洁。**要求保留原版不动**，另开一个只展示动态部分的页面。

**产出文件（全新，与原版完全隔离）**
- `gather.html` — 只有：顶栏（标题 + 返回链接）、SVG 舞台、字幕行、底部悬浮控制条
- `assets/gather.css` — 深色主题，CSS 变量驱动
- `assets/gather.js` — 独立动画引擎，不依赖 app.js

**原版保护**：`index.html` / `assets/style.css` / `assets/app.js` 一行未改（时间戳可验证），完整版页面保留作参考。

**设计转向**
- 浅色 → 深色（`--bg:#07090f`），背景三团缓慢漂移的 aurora 光晕
- 主体从"多区块滚动页"变成"单屏聚焦演示"：`body{overflow:hidden}`，控制条悬浮在底部
- 动画升级：数据包发光 + 两段拖尾（沿路径回溯 26/50 单位）、落地时槽位弹跳 + 涟漪圆环、连线流动虚线
- 进度条带阶段刻度点，键盘 Space/←/→/R

**深色版踩的坑**
1. **tall 布局的总线画错**：用 `rotate(90)` 画横向总线，旋转后变成一条竖线直接穿过 GPU0 卡片。
   窄屏根本不该画总线 → 改为三路连线直接扇入 + 底部文字标签。
2. **窄屏大片留白**：SVG 用 `preserveAspectRatio="xMidYMid meet"`，viewBox 560×500 在 390px 宽容器里
   只能缩到 348px 高，剩下的变成空隙，而字幕被 `flex:1` 顶到屏幕底。
   修法：窄屏 `.stagebox{flex:0 1 auto;height:auto}` + `#stage{height:auto}`，让舞台按内容高度自适应。
3. **误判"彩色圆圈是 bug"**：截图抓到的是落地涟漪动画的中间帧，实为正常。排查方式：
   `getComputedStyle` 读槽位与 `#lFx` 子元素的 fill/stroke/opacity/animationName。

### 第三版：白底 + 极简文字 + 左右结构统一

**用户反馈**：文字太多；窄屏是上下结构、宽屏是左右结构不一致；左右结构下箭头对不齐、虚线变实线；不喜欢黑色主题。
**要求**：全部使用左右结构。

**改动（仍只动 gather.html / gather.css / gather.js，原版三个文件继续零改动）**

1. **主题**：深色 → 白底（`--bg:#f4f6fb`），顶部淡紫/淡蓝径向渐变，卡片纯白 + 柔和阴影。
2. **文字大幅精简**：SVG 内文本从 30+ 处降到 15 处，且只剩 GPU 编号与 A/B/C/D 字母。
   - 删除：角色标签（收集者·dst / 贡献者·src）、rank 徽章、"缓冲区 1/4 段"、"本段 1 段·保持不变"、
     "GPU 互联总线 · NVLink / PCIe"、中间竖向色块、阶段标注文字
   - 保留：顶栏标题、dst 徽章（仅 GPU0）、GPU 编号、槽位字母、字幕一行短句
   - 字幕从整段描述压缩成 6 条短句（如 `rank 1 → rank 0：B`）
3. **统一左右结构**：删除 `GEO_TALL`（上下布局）。`GEO.desktop` 与 `GEO.narrow` 都是 dst 在左、源卡在右竖排，
   窄屏只改密度（viewBox 1200×640 → 400×600），不再切换结构方向。
4. **箭头对位修复（核心）**：原实现三条线全部汇聚到同一个点。改为
   **dst 的 4 个槽位竖排**（A/B/C/D 纵向），每条连线指向自己 rank 对应的那个槽位
   （rank1→B槽、rank2→C槽、rank3→D槽），终点 = 槽位右边缘外侧 4px，箭头尖端正好贴住色块。
   实测垂直偏差 dy=0.0。
5. **虚线恒定**：原代码传输完成后 `stroke-dasharray='none'` → 变成实线。改为全程保持虚线
   （静止 `8 7`、传输中 `9 7` + dashoffset 流动、完成后 `8 7` + 降低透明度）。
6. **层级修正**：SVG 图层顺序改为 `lCards → lChips → lWires → lFx`，
   否则连线上的箭头会被槽位色块压住看不见。

**本轮踩的坑**
- SVG `preserveAspectRatio="xMidYMid meet"`：viewBox 比例与容器比例不一致时必然留白。
  窄屏想撑满就得让 narrow 的 viewBox 比例贴近竖屏容器（400×600），而不是只调 CSS。
- 箭头 marker 的 `refX` 要等于尖端坐标（8），否则箭头与目标之间有肉眼可见的偏移。

### 第四版：卡片尺寸统一 + 槽位居中 + 箭头指向卡片

**用户反馈**：GPU0/1/2/3 尺寸不一致；ABCD 在 GPU 里没居中；箭头指向 GPU0 内部的 BCD 槽位，改成指向 GPU0 即可。
**约束**：ABCD 移动特效保持现状，不改。

**三项改动**
1. **卡片尺寸统一**：抽出 `L.card = {w, h}`，四张卡共用同一尺寸
   （desktop 210×190 / narrow 150×150），src 卡不再用独立宽高。
2. **槽位居中**：
   - dst 的 4 个槽从竖排改为 **2×2 网格**，整组在标题区下方水平垂直居中
   - 源卡的 1 个槽在卡片内水平垂直都居中
   - 槽改为正方形（desktop 44×44 / narrow 32×32），视觉更整
   - dst 徽章从标题下方移到标题右侧（原位置会被槽位遮住）
3. **箭头指向卡片而非内部槽位**：终点改为 GPU0 卡片右边缘外侧 4px，
   三个落点按 `dst.y + dst.h * (0.24 + 0.26*(r-1))` 分布，避免三条线重叠。
   实测终点 x 全部 = 卡片右边缘+4，均在卡片外部。

**验证结论**
- 四卡尺寸：desktop 210×190 ×4、narrow 150×150 ×4 → 完全统一
- 水平偏心：源卡 0.0、dst 网格组中心偏移 0.0
- 箭头：终点均在 GPU0 卡片右边缘外侧，不再进入卡片内部
- 虚线恒定、文字 15 处、无溢出 —— 全部保持

**几何参数集中管理**
```
L = { view, card:{w,h}, dst:{x,y}, src:{x,ys[]}, slot:{sw,sh,gap}, hdr }
```
`hdr` = 标题区高度，槽位区 = `geo.y + hdr` 到 `geo.y + geo.h - 14`，
在此区域内居中。改版时只动 GEO 两个对象即可。

### 第五版：矩形卡片 + 标题条 + ABCD 横排

**用户反馈**：GPU 框是正方的不好看要改矩形；顶部细横条太丑要去掉；标题行填充原细横条颜色、标题靠左；
GPU0 里的 ABCD 要横向排布且居中。
**约束**：箭头、数据块迁移特效保持不变。

**改动**
1. **卡片改矩形**：`card: {w:300, h:152}`（桌面）/ `{w:196, h:108}`（窄屏），宽高比约 2:1。
   因 GPU0 要横排 4 个槽，卡片宽度必须加大。
2. **去掉顶部细横条**：删掉那个 `h:3.5` 的 rect。
3. **标题条**：改用 SVG path 绘制**上圆角矩形**填充原横条颜色
   （dst `#7c3aed` 紫、源卡 `#dfe3ee` 灰）。
   path 用 `A` 弧线命令画两个上角，圆角半径与卡片 rx(14) 一致 —— 用 rect 会切出直角缺口。
   标题文字 `text-anchor: start` 靠左（左边距 16px），dst 标题改白色（紫底），源卡保持灰色。
   dst 徽章移到标题条最右侧（半透明白底 + 白字）。
4. **ABCD 横排**：dst 的 4 槽从 2×2 改为**单行横排**，整组在标题条下方水平垂直居中
   （实测组居中偏差 0.0）。源卡单槽仍居中。

**本轮踩的坑**
- 标题条若用 `<rect>` 画，卡片上方的圆角会被切出直角缺口 → 必须用 path + 弧线命令。
- 窄屏下 GPU0 与 GPU2 水平重叠：dst 右边缘 226 vs src 左边缘 232，只差 6px →
  缩窄卡片（214→196）并把 src.x 从 232 挪到 268，间距提到 62px。
- 改 `hdr`（标题条高度）后卡片内剩余空间变化，卡片高度要同步调整，否则槽位区比例失衡。

**最终几何（第五版）**
```

         slot 46×46 gap12, hdr 34
```

### 第十版：控制条改中性白灰

**用户反馈**：播放按钮不要红色了，换个不显眼的颜色；进度条也是，换成白灰之类的。

**改动**：新增一组控制条专用中性色变量，替代原先的红色/紫色：

```
--ctl-ink:   #6b7488   播放键 / 图标主体
--ctl-ink-2: #7d8699   悬停
--ctl-track: #e6e9f0   进度条轨道
--ctl-fill:  #8b93a6   进度条已播放段
--ctl-ring:  rgba(107,116,136,.2)
```

- 播放键：红色 `#ef2b4d` → 深灰蓝 `#6b7488`，阴影也换成中性灰调
- 进度条：填充由紫色 `--accent` → 中灰 `#8b93a6`，轨道 → 浅灰 `#e6e9f0`，
  滑块保持白色 + 中性灰光晕环
- 步进键图标颜色、键盘焦点环、字幕编号徽章全部并入中性色体系
  （编号徽章由实心深色块改为浅灰底 + 深灰字，存在感进一步降低）

### 第十三版：文案改「份」+ 左右各外扩 2%

**用户要求**：日志「各卡各持 1 段」→「每张卡持有 1 份数据」，段改份；
rank0 向左挪 2%，rank1/2/3 向右挪 2%。

**改动**
1. 文案：`每张卡持有 1 份数据`、`目标卡预留 4 份缓冲`（其余「1 号卡发送 B」等不变）
   注意 `<b>` 后不要留空格，否则中文会出现可见间隙。
2. 位置：`dst.x 50 → 21.4`、`src.x 640 → 668.6`（各 28.6 viewBox 单位）

**2% 的换算方法（重要）**
页面百分比 ≠ viewBox 单位。必须先求 SVG 的实际渲染缩放比：
```
s = (最右卡右边缘px − 最左卡左边缘px) / (对应 viewBox 坐标差)
  = (1163.5 − 266.4) / (940 − 50) ≈ 1.008
```
则「页面 2%」= `视口宽 × 0.02 / s` = `1440 × 0.02 / 1.008 ≈ 28.6` 单位。

**关键：不能靠扩大 viewBox 来挪位置**
内容居中时，把 viewBox 左右各加 d、内容也各加 d，屏幕位置恒不变（居中的抵消效应）。
所以只能改内容相对 viewBox 的坐标。

**实测结果（1440×900）**

|---|---|---|
| 最左卡左边缘 | 18.5% | **16.5%** |
| 最右卡右边缘 | 80.8% | **82.8%** |
| 总跨度 | 62.4% | **66.4%** |

1920/1280 下因缩放比不同，实际偏移约 ±1.9%（固定 viewBox 位移，非固定百分比）。

窄屏未动：narrow 的 dst.x=6、src 右边缘距 viewBox 边界仅 8 单位，已无可外扩空间。

### 补充：聚焦范围扩展到飞行包与链路

用户发现「悬停 D 时虚线上飞行的 B 还有颜色」。三处一起纳入：
- 数据包 `g.pkt` 加 `data-l`（fill 变灰，opacity 仍由 JS 控制）
- 链路 `path.wire` 加 `data-l`，CSS 覆盖 `stroke`
- 箭头 `path.arw`（在 `defs` 的 marker 内）加 `data-l`，CSS 覆盖 `fill`

**关键约束：CSS 的 opacity 规则必须排除 `.pkt` 和 `.wire`**
这两类元素的 opacity 由 `paint()` 逐帧写 attribute（显示/隐藏、active/done）。
CSS 规则的优先级高于 presentation attribute，一旦命中：
① 隐藏的包/线会被强制显示（opacity 被改成 .78）；
② 加在它们身上的 `transition: opacity` 会让出现/消失变滞后。
所以规则统一写成 `[data-l]:not(.pkt):not(.wire)`，只保留它们的 fill/stroke 覆盖。

**另一坑：`querySelectorAll('#stage [data-l]')` 会把 `defs` 里的箭头算进来**
箭头在 `<defs>` 中、DOM 顺序最靠前，按字母筛元素时容易被它抢先命中，
`getBoundingClientRect()` 返回 0 尺寸 → 点击坐标落在 (0,0) → hover 测不出来。
定位图例块要用 `.whole g[data-l=D]` 这种明确路径。

### 第二十一版：字幕改居中 + 修正色块与文字的垂直对齐

- 色块 `vertical-align` 从 **-3.5px → +1.3px**，与文字垂直中心对齐

### 第二十五版：修「点进度条，填充没落在鼠标位置」

**根因**：分段条 6 段**等宽**，但每步的时间区间**不等长**
（0.10 / 0.10 / 0.18 / 0.18 / 0.18 / 0.26）。原生 range 是线性的，
点击位置 → 线性时间 → 再按「段内比例」渲染填充，两次换算不同源，于是错位。
例：点条宽 50% 得 t=0.5，落在第 4 段（0.38~0.56）的 67% 处，
填充边界实际出现在条宽 61% —— 肉眼可见差 11%。

**修法**：在 range 与时间之间加一层互逆换算
- `tToV(t)`：时间 → 视觉位置（定位第几段 + 段内比例）
- `vToT(v)`：视觉位置 → 时间（同上反向）
- `paint()` 里 `sc.value = tToV(t)*1000`；input 监听里 `seek(vToT(v/1000))`

于是滑块、填充、鼠标三者统一，点哪填哪。

**实测**：点 12/30/50/68/85% 五处，填充边界与点击点差 -3.0~+3.8px（条宽 1200）；
拖拽 30%→70% 差 2.5px；两端 0.2%→t=1、99.8%→t=999。
残余误差来自段间 5px gap（点落缝里会吸附到段边界），量级 0.3%，可忽略。

**测试注意**：`box.x + box.w` 是 rect 的排他右边界，用它当点击坐标会落到元素外
（表现为 t 不变，容易误判成边界 bug）——测最右端要用 0.998。

### 第三十版：修「落位放大动画只有第一轮生效」

**症状**：刷新后第一遍播放，数据块落地有放大弹跳；循环第二遍起就没有了。

**根因**：重放 CSS 动画的标准做法是 `removeClass → 强制回流 → addClass`，
但原代码写的是 `void s.g.offsetWidth` —— **SVG 元素没有 offsetWidth**（是 undefined），
这行等于空操作，浏览器把"删-加"合并成同一次样式计算，认为 class 没变 → 动画不重启。
第一轮能用，只是因为 class 从无到有。

**修法**：改用 `void s.g.getBoundingClientRect()`（对 SVG 元素有效，会强制刷新样式与布局）。

**验证**：连续三轮 seek 跨越 B 的落地时刻（250 → 520），每轮都在动画启动 90ms 后采样：
`transform` 分别是 1.117 / 1.024 / 1.024，`getAnimations()` 均为 1 个且 `playState=running`。

**同类坑**：在 SVG 里做「强制重排重启动画」时，`offsetWidth / offsetHeight / clientWidth`
全部不可用，要用 `getBoundingClientRect()` 或 `getBBox()`。

### 第三十八版：点击数据块「钉住」聚焦

**需求**（用户口述）：点击 A → 其他灰；此时悬停 B 显示 B；鼠标移走回到 A；再点 A 取消、点别的改钉。

**实现**（`assets/cv/focus.js` 整体重写，约 90 行）
```
hover   = 指针当前指向的字母
pinned  = 被点击钉住的字母
active() = hover || pinned     ← 唯一的真相来源
```
- `pointerover` 更新 hover → render()
- `pointerleave` 清 hover → render()
- `click`：命中 `[data-l]` 时 `pinned = (pinned === l ? '' : l)` → render(true)
- render 里用 `applied` 记上次写入的值，避免每帧重写 DOM；
  但 `data-pinned` 每次都写（它和 data-focus 不是一一对应）

**边界决策**
- 点舞台空白**不**取消钉住（用户只说了「再点 A 取消」，不额外扩展行为）
- 钉住时给块加描边的方案试过又撤了：描边压在满色块内缘很脏，且会命中
  包里同一字母的 3 层（主体 + 2 拖尾）。改为只加 `cursor: pointer` 做可发现性。

**实测（13 步交互序列，gather，1440×900）**
| 步骤 | focus | pinned |
|---|---|---|
| 悬停 A | A | — |
| 点 A | A | A |
| 移空白 | **A** | A |
| 悬停 B | **B** | A |
| 移空白 | **A** | A |
| 再点 A | A | — |
| 移空白 | 无 | — |
| 点 B → 移空白 | B | B |
| 直接点 A → 移空白 | A | A |
| 点舞台空白 | A（不变） | A |

三页 + 窄屏全部通过：gather/scatter 钉 B 时 2 张卡置灰，
broadcast 钉 B 时 0 张卡置灰（每张卡都持有 B）——与 `keepCards` 语义一致。

**踩坑**：改了 `focus.js` 后测试完全没反应，`pinned` 一直是空。

### 第三十九版：新增 Reduce 页面（N→1，N 份相加）

**新文件**：`reduce.html` + `assets/reduce.js`。

**语义难点**：gather 是「N 段拼成一份」（数据量膨胀），reduce 是「N 份逐元素相加」
（数据量不变）。所以在「一份 = A B C D 四段」的模型下：
每张卡都持有一整份（4 槽），归约后 rank0 的 4 个槽**还是 4 个**，只是每格变成了「和」。

**「和」怎么表达**（这是本页唯一的新设计）
`sumColor(base, n) = mix(base, '#190d33', 0.19 * (n - 1))`，n = 已归约份数（1~4）。
- n=1 原色；每汇入一份深一档；n=4 时 A 从 `rgb(124,58,237)` → `rgb(69,33,133)`
- 初版系数用 0.13，肉眼几乎看不出差异（只到 88,42,169），提到 0.19 才够明显
- 隐喻：颜色越浓 = 加得越多。配合字幕「rank0 得到 4 份之和」

**复用上的两件事**
1. 把 broadcast 里的本地 `drawBatch()` 提升为 **`CV.drawPacketBatch(parent, slot, items)`**
   （kit 第 150 行），返回 `{g, head, t1, t2, half}`，与 `placePacket` 兼容。
   broadcast.js 因此删掉 52 行，两页共用同一份实现。
2. 连线方向照搬 gather（源卡左边缘 → 目标卡右边缘，三个落点 0.28/0.50/0.72）。

**步骤只有 5 段**（其它三页是 6 段）：归约的叙事是「起始 → 三份依次加入 → 完成」，
天然 5 步。controls 的分段数由 `STEPS.length` 决定，不用改。

**实测（1440×900）**
- 结构：4 卡 / 16 槽 / 3 线 / 3 包 / **5 段**；角色 `0:dst 1:src 2:src 3:src`
- 四张卡从第一帧起都是满的 [A B C D]（归约是读取，不清空源卡）
- 结果卡颜色逐档加深：`t=0 → 124,58,237`；`t≈0.26 → 112,53,215`；
  `t≈0.45 → 100,47,192`；`t=1 → 69,33,133`
- 悬停 A：四张卡全保留（keepCards 返回全部）
- 窄屏 380×720 无溢出

**四页综合回归**：卡 4 / 槽 7·7·16·16 / 线 3 / 段 6·6·6·5；
播放 1s → t≈184；完成态与钉住全部正常；控制台只有 favicon 404。


### 第四十版：Reduce 改成 8 步（飞行 + 消化），目标卡拆两排

**为什么改**：原来的 5 步会让人误读成「rank0 先把 4 份堆起来再压缩」。
真实的 reduce 是**通信与计算同时进行**，rank0 始终只有一个累加器 ——
每飞过来一份就立刻折进去。所以要把「到达」「折进」拆成两个动作。

**语义明确写在 reduce.js 顶部注释里**，以后不要改回堆叠式。

**① 目标卡变高，两排**
| | 桌面 | 窄屏 |
|---|---|---|
| `card`（源卡） | 300×170 | 146×126 |
| `targetCard` | 300×**206** | 146×**140** |
| `target.y` | 237（中心 340 不变） | 290（中心 360 不变） |
| `areaPad / rowGap / calcGap` | 12 / 12 / 10 | 9 / 8 / 7 |

- 上排 = 累加器（常驻，`chips[target]`）
- 下排 = 刚到的整份（`ghost[from]`，画在 `lFx` 层，可自由移动）
- 下排**常设 4 个空槽**（画在 `lChips`），让人一眼看出「这里预留了接收位」；
  实体块浮在上面，折进去后空位重新露出来

**② 8 步时间轴**（`duration: 10400`，飞行 0.16 / 消化 0.08）
```
0.00 四卡各持整份            0.49 逐段相加，累加到 3 份
0.09 rank1 的整份送往 rank0   0.57 rank3 的整份送往 rank0
0.25 逐段相加，累加到 2 份    0.73 逐段相加，累加到 4 份
0.33 rank2 的整份送往 rank0   0.81 结果只留在 rank0
```
每条 flow = `{from, start, arrive, end}`：`start→arrive` 飞行，`arrive→end` 消化。
`doneParts()` 用 `t >= f.end` 计份数，所以消化期间颜色只做插值、不跳档。

**③ 折进节奏**（`HOLD=0.32, OFFSET=0.10, MERGE=0.38`，都在消化段内归一化）
`mergeE(p, i) = clamp((p - HOLD - i*OFFSET) / MERGE, 0, 1)`
- 前 32% 驻留（让落位弹跳演完），A~D 再依次错开折进去
- 折进 = 上移一行 + 缩到 0.70 + 淡出；累加器同时做颜色插值并 `spawnPulse` 弹一下

**④ 「计算」标签**
- 两排下方的小方牌，文字「计算」，悬停浮出 `sum · avg · max · min`（窄屏 `sum · avg`）
- 显示区间：**第一次折进开始 → 最后一次折进结束**（`t ∈ [0.25, 0.81)`）
  飞行途中不隐藏，否则会闪 3 次；归约结束后收起，因为是「计算中」的指示
- 结构：`.calc-wrap`（JS 控显隐 `data-on`）> `.calc-chip` + `.calc-tip`（CSS hover 控 tip）
- tip 用**深色气泡**（#363b4e），因为它跨在卡片底边上，白底白卡会糊在一起

**⑤ 踩了两个坑**

1. **黑块**：两排数据全渲染成黑色。查 `getComputedStyle` 的 fill 明明是正确颜色。
   真凶是 `CV.mix` 只认 hex，而 `sumColor()` 返回的是 `rgb(...)` ——
   二次混合时 `parseInt('rg', 16)` = NaN → `rgb(NaN,NaN,NaN)` → 黑。
   已让 `CV.mix` 的 `hex()` 先试 `/^rgba?\(/`，兼容自己产出的格式（向后兼容）。

2. **ghost 的黑块/渲染异常**：外层 `.ghost-g` 用 SVG `transform` 做融合位移，
   内层 `.slot-g` 挂 CSS `slot-pop` 动画 —— 两层 transform 叠加时 Chrome 会把
   SVG 分组提成合成层，填充色渲染丢失。
   改法：**弹跳也用 JS 算**（`popOf(q)`，曲线对齐 slotPop 的 0.35→1.16→1），
   与融合位移合并成**一个** transform：
   `translate(cx(1-k), cy(1-k) - rowStep*e) scale(k)`，`k = pop.k * (1-0.30e)`。
   附带好处：拖进度条也能复现弹跳（CSS 动画不能）。
   另外 `.ghost-g` 不要加 `will-change`，同样会渲染成黑块。

3. 隐藏中的 ghost 要 `pointer-events: none`（`.ghost-g[opacity="0"]`），
   否则透明块会截获 hover、误触发聚焦。

**⑥ 连线落点**
三条线不再按整卡高度分布，而是**全部收在第二排的高度带**内
（`baseRatio = rowCenter / dst.h`，步长 `slot.sh*0.42/dst.h`）——
数据确实是奔着那一排去的，落点跟着语义走。

**⑦ 新文档**：`docs/待讨论-Ring与Tree.md`，记录 Star/Ring/Tree 的差别与 5 个待定问题。
关键结论：本页画的是 Star（Direct）reduce，**不是 NCCL 的默认实现**；
Ring 赌带宽（延迟 ∝ N），Tree 赌延迟（∝ log N），NCCL 按消息大小 + 拓扑现场选。

### 第四十三版：Reduce 布局重构（居中 + 计算方框独立位置 + 间隔 +0.1s）

**用户三点要求**
1. 第二步「预留缓冲」后，rank0 里两份数据**上下左右居中**，且**不预留**计算方块的位置
2. 第 4 步（消化步）：先上下拉宽 rank0 → 展示计算方框 → 进行计算 → 算完方框消失、卡片收窄
3. 计算时 ABCD 融合间隔 **+0.1s**

**① 几何重写：卡片顶边固定，中心不再固定**
原来 `cardTop = cy - h/2`（中心固定），导致卡片长高时数据块整体上下漂移。
改成**顶边固定、内容从顶边往下推**：
```
h1 = hdr + areaPad*2 + sh              一份数据
h2 = h1 + sh + rowGap                  两份数据（不含方框位置）
h3 = h2 + calcGap + calc.h + areaPad   计算中
第一排   = 顶边 + hdr + areaPad
第二排   = 第一排 + rowStep
计算方框 = 第二排 + sh + calcGap
```
- 两排数据在卡片里上下居中（上下留白各 areaPad）、左右居中（totalW 居中）
- 计算方框永远卡在第二排下面，卡片多高都不挤
- **数据块位置全程是常量** —— 融合过程中一点不漂

**② 时间轴改成「秒」为单位**
`T = {init:0.6, prealloc:0.7, fly:1.7, pop:0.6, grow:0.4, merge:1.3, shrink:0.4}`
`CYCLE = fly+pop+grow+merge+shrink = 4.4`，`TOTAL = 15.0s`
每份分四拍：飞 → 落位弹跳 → **拉宽出方框** → 融合 → 收窄。
STEPS 的 t 用 `N(sec) = sec / TOTAL` 归一化。

**③ 间隔 +0.1s**
旧：`mergeE(p,i) = clamp((p - i*0.15)/0.55, 0, 1)`，p 是归一化进度 → 实际间隔 0.15×1.0s = 0.15s
新：`mergeE(p,i) = clamp((p*T.merge - i*GAP)/SEG, 0, 1)`，`GAP=0.25s`、`SEG=0.55s`
→ 间隔 0.15s → **0.25s（正好 +0.1s）**，单段时长不变。

**④ CSS 坑：`.calc-wrap` 的 opacity 过渡会和逐帧插值打架**
原来靠 `data-on` + CSS `transition: opacity .28s` 切换显隐。
现在卡片高度是连续插值的，方框要在拉宽/收窄过程中渐隐渐现，
所以改成 **JS 直接写 `style.opacity`**，并把 CSS 的 transition 去掉
（JS 里也加了 `g.style.transition='none'` 兜底）。

**⑤ 连线落点重排**
三条线原来挤在第二排的窄带里（step = sh*0.42），视觉上像一条。
改成沿目标卡右缘按高度比例分散：`ty = cardTop + cardH * (0.30 + 0.20 * k)`，
和 gather 的做法一致。卡片长高时落点跟着走，始终落在卡片范围内。

**实测（1440×900 / 390×844）**
- 9 段进度条；t=0 rank0 只有一行
- 预留步结束：卡片两排数据居中，下排 4 个虚线空位
- 消化步：卡片拉宽 → 「计算」方框出现在第二排下方 → 融合 → 方框淡出、卡片收窄
- 终态：三张源卡全空，rank0 上排深色、下排空位、卡片恢复两排高度
- gather / scatter / broadcast 回归无变化

**④⑥ 落位弹跳对齐 gather（用户反馈「接收完数据有放大跳动特效，明显不一样」）**

关键事实：gather 的落位弹跳是 CSS `.slot-pop`：
`animation: slotPop .55s cubic-bezier(.2,.9,.3,1.45)`，
关键帧 `0% scale(.35) → 55% scale(1.16) → 100% scale(1)`。

**因为 y 控制点 1.45 > 1，曲线会过冲，实际峰值是 1.28 而不是 1.16** ——
「啪」一下的弹性感就来自这里。之前 reduce 用手写的 easeOutQuad 近似，
峰值只有 1.16 且是软减速，所以看着明显"软"、不像 gather。

改法：
- `assets/cv/dom.js` 新增 `CV.cubicBezier(x1,y1,x2,y2)`（牛顿迭代 8 次 + 二分兜底），
  在 JS 里原样复刻 CSS 曲线
- reduce 的 `popOf` 改用 `POP_EASE = CV.cubicBezier(.2,.9,.3,1.45)`，
  按 CSS 的方式分两段（0→55%、55%→100%，每段各自套这条缓动）
- **opacity 要自己 clamp 到 1**（CSS 会把 opacity 计算值钳进 [0,1]，JS 不会，
  不过冲那段会算出 1.15 的 opacity）

实测两页曲线逐点吻合（ms, scale）：
gather `44:0.899 94:1.184 144:1.280 194:1.284 244:1.239 …`
reduce `54:0.901 116:1.207 178:1.288 241:1.269 …`（reduce 的 T.pop=0.6s 略慢于 CSS 的 0.55s，形状相同）

**为什么落位弹跳不能用 CSS 动画**：ghost 外层要写融合位移的 transform，
内层再挂 CSS 动画 = 两层 transform 嵌套，Chrome 会把 SVG 分组提成合成层、
填充色渲染成黑块（老坑）。所以只能 JS 算，曲线就得自己复刻准。

### 卡片布局：2×2 网格 = 天然的顺时针环
- 网格的四条边正好构成一个环：rank0(左上) → rank1(右上) → rank3(右下) → rank2(左下) → rank0
  顺时针，4 条连线零交叉，也正是 NCCL ring all-gather 的真实形状。
- 卡片列 = `r & 1`，行 = `r >> 1`，`cardGeo(r)` 由行列直接算出。
- 这是**第四种卡位形态**：gather/scatter/broadcast 是「一列多卡 + 左侧单目标」，
  reduce 是「左侧目标 + 右侧三源」，All-Gather 是 2×2 网格。

### 语义
- All-Gather 是**复制**：源卡送出的那份自己还留着（与 reduce 的消耗相反）。
- 槽位固定：第 k 个 rank 恒持第 k 段 → 每卡第 k 个槽永远是同一段
  → 三轮之后四张卡长得一模一样（这是本页最漂亮的点）。
- 每轮各发「本轮刚拿到的那段」：第 1 轮发自己的，第 2 轮发第 1 轮收到的，
  第 3 轮发第 2 轮收到的。路由由 `carried` 数组自动推演，不用手写表。

### 槽位三态复用 `CV.setSlot`
own/done = 实心彩色；waiting（正在路上）= 浅紫底「···」；empty = 浅灰虚线框。
