    Gather 收集

    Scatter 的反向——每人手里有一块数据，全部收拢到一个人手上。 4 张 GPU 各持一份，rank 0 最终拿到拼好的完整数据，其余各卡保持不变。

    约 8 秒 · 可拖动进度条逐帧观察
    坐标系 发 ↔ 收
    1 个人发 全体发 1 人收 P2P Send / Recv Reduce Scatter Gather ← 当前 全体收 Broadcast All-Gather All-Reduce Reduce-Scatter All-to-All

    目标 dst rank 0 只有它拿到拼好的结果
    数据量变化 1份 → 4份 dst 侧缓冲区膨胀 N 倍

        !
        NCCL 后端不直接支持 gather

        PyTorch 官方后端能力表中 gather 对 NCCL 标记为不支持。 GPU 场景通常改用 all_gather 后在本地取切片，或用 dist.gather_object 处理任意 Python 对象。

        i
        发送方数据不会被销毁

        Gather 是复制语义：rank 1/2/3 通信后仍各自保留本段数据， 只有 dst 的缓冲区被撑大。这正是它与 Reduce（汇总压缩）的分水岭。

        每个人手里捏着一张扑克牌交给庄家，庄家凑齐一整副牌；其余人不改手里的牌。
