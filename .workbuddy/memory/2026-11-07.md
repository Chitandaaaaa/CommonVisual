# 2026-11-07 · memory 纳入版本库

## 做了什么
1. `.gitignore` 由整目录忽略 `.workbuddy/` 改为放行 memory：`.workbuddy/*` + `!.workbuddy/memory/` + `!.workbuddy/memory/**`（必须用 `/*` 而非 `/`，否则 git 不进目录、`!` 无法把子文件捞回来）。`.zcode/` 保持整目录忽略。
2. `MEMORY.md` 新增「文件构成」段（本文件 / 日志 / `from-070d080b-20261030/` 快照各自定位 + 多机并发提醒）、文末「日志索引」表（15 条）。
3. 「分支与推送」改成现行事实：`origin.url` 已是 SSH，直接 `git push`；删 worktree 不必再手工备份 memory（旧约定作废）。
4. `2026-10-30.md` 里 1 处 `/Users/lxm/...` 绝对路径改成 `<repo>`，入库后不再带机器路径。

## 判据
「只存在于一台机器、又被 git 忽略的资产」＝定时炸弹。MEMORY.md 自己记着「删 worktree 会永久丢 memory」，把它入库是从根上消掉这个风险，顺带拿到 `git blame` 级的历史。
边界：只放行 memory，不放行整个 `.workbuddy/`（那里可能长别的本机状态）。

## 坑
- gitignore 不能对「已排除的目录」再 `!` 回子文件，必须把父级排除写法从 `dir/` 改成 `dir/*`。用 `git check-ignore -v <file>` 验证：输出里带 `!` 的规则命中才算放行成功。
