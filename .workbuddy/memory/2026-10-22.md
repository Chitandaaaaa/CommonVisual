# 2026-10-22

## CommonVisual 分布式通信原语可视化 · Gather 页面设计

**项目**：从零搭建的 Web 可视化项目，素材来自 `分布式通信原语详解.md`（NCCL 8 种集合通信原语）。
首个原语选定 **Gather（收集）**。

**产出文件**
- `index.html` — 单页结构（Hero / 指标卡 / 前后对照 / 动态演示 / 步骤拆解 / 代码 / 原语对比表）
- `assets/style.css` — 浅色主题，CSS 变量驱动，响应式断点 1080 / 780 / 520
- `assets/app.js` — 数据模型 + SVG 舞台构建 + 时间轴状态机 + 代码高亮

**关键技术决策**
- **舞台用 SVG 而非 DOM**：连线需要精确的三次贝塞尔路径，`getPointAtLength()` 让数据包能沿路径运动。
- **双布局几何**（`GEO_WIDE` / `GEO_TALL`）：宽屏 dst 在左、源卡竖排右，连线经中间竖直总线汇聚；
  窄屏（<780px）dst 在上、源卡横排下，链路自下向上扇入。`syncLayout()` 在 resize 时重建舞台并重绘。
- **时间轴归一化 0→1**：`T` 常量定义各阶段区间（init / alloc / 3 段传输 / done），
  `paint(t)` 是纯函数式渲染，拖动进度条即回放任意时刻，天然支持 scrub。
- **代码高亮用单次正则扫描**（`new RegExp` 而非字面量，因为关键词表要插值）：
  字符串 / 注释 / 数字 / 关键字 / 函数名一次匹配，避免二次 replace 破坏已生成的 span。
- **坐标系象限图按原文档对齐**：Gather 在「全体发 × 1 人收」，Scatter 在「1 个人发 × 1 人收」。

**内容要点**
- PyTorch `dist.gather` 需要仅 dst 传 `gather_list`，其余传 `None`。
- **NCCL 后端不支持 `gather`**（官方后端能力表标记为 ✘），GPU 场景用 `all_gather` 取切片或 `gather_object` 替代；
  页面给出了点对点手写的等价实现。
- Gather 是复制语义：源卡数据不被搬走，只有 dst 缓冲区膨胀 N 倍 —— 与 Reduce（汇总压缩）的分水岭。

**验证方式（可复用）**
- jsdom 无头测试：DOM 构建产物计数 + 时间轴各关键点状态断言 + 交互回归。
- 真实浏览器：系统 Chrome `--headless=new --remote-debugging-port` + CDP（ws 直连）截图与运行时检查。
  注意：沙箱内 `npm i agent-browser` 的 Chromium 下载会被代理超时阻塞，改用系统 Chrome 更可靠。
- 注意 Bash 调用结束会回收后台进程，静态服务与 Chrome 必须写在同一次调用脚本里。

## 第二版：精简动态演示页（深色）

**用户反馈**：完整版信息量太大、不够简洁。**要求保留原版不动**，另开一个只展示动态部分的页面。

**产出文件（全新，与原版完全隔离）**
- `gather.html` — 只有：顶栏（标题 + 返回链接）、SVG 舞台、字幕行、底部悬浮控制条
- `assets/gather.css` — 深色主题，CSS 变量驱动
- `assets/gather.js` — 独立动画引擎，不依赖 app.js

**原版保护**：`index.html` / `assets/style.css` / `assets/app.js` 一行未改（时间戳可验证），完整版页面保留作参考。

**设计转向**
- 浅色 → 深色（`--bg:#07090f`），背景三团缓慢漂移的 aurora 光晕
- 主体从"多区块滚动页"变成"单屏聚焦演示"：`body{overflow:hidden}`，控制条悬浮在底部
- 动画升级：数据包发光 + 两段拖尾（沿路径回溯 26/50 单位）、落地时槽位弹跳 + 涟漪圆环、连线流动虚线
- 进度条带阶段刻度点，键盘 Space/←/→/R

**深色版踩的坑**
1. **tall 布局的总线画错**：用 `rotate(90)` 画横向总线，旋转后变成一条竖线直接穿过 GPU0 卡片。
   窄屏根本不该画总线 → 改为三路连线直接扇入 + 底部文字标签。
2. **窄屏大片留白**：SVG 用 `preserveAspectRatio="xMidYMid meet"`，viewBox 560×500 在 390px 宽容器里
   只能缩到 348px 高，剩下的变成空隙，而字幕被 `flex:1` 顶到屏幕底。
   修法：窄屏 `.stagebox{flex:0 1 auto;height:auto}` + `#stage{height:auto}`，让舞台按内容高度自适应。
3. **误判"彩色圆圈是 bug"**：截图抓到的是落地涟漪动画的中间帧，实为正常。排查方式：
   `getComputedStyle` 读槽位与 `#lFx` 子元素的 fill/stroke/opacity/animationName。

## 第三版：白底 + 极简文字 + 左右结构统一

**用户反馈**：文字太多；窄屏是上下结构、宽屏是左右结构不一致；左右结构下箭头对不齐、虚线变实线；不喜欢黑色主题。
**要求**：全部使用左右结构。

**改动（仍只动 gather.html / gather.css / gather.js，原版三个文件继续零改动）**

1. **主题**：深色 → 白底（`--bg:#f4f6fb`），顶部淡紫/淡蓝径向渐变，卡片纯白 + 柔和阴影。
2. **文字大幅精简**：SVG 内文本从 30+ 处降到 15 处，且只剩 GPU 编号与 A/B/C/D 字母。
   - 删除：角色标签（收集者·dst / 贡献者·src）、rank 徽章、"缓冲区 1/4 段"、"本段 1 段·保持不变"、
     "GPU 互联总线 · NVLink / PCIe"、中间竖向色块、阶段标注文字
   - 保留：顶栏标题、dst 徽章（仅 GPU0）、GPU 编号、槽位字母、字幕一行短句
   - 字幕从整段描述压缩成 6 条短句（如 `rank 1 → rank 0：B`）
3. **统一左右结构**：删除 `GEO_TALL`（上下布局）。`GEO.desktop` 与 `GEO.narrow` 都是 dst 在左、源卡在右竖排，
   窄屏只改密度（viewBox 1200×640 → 400×600），不再切换结构方向。
4. **箭头对位修复（核心）**：原实现三条线全部汇聚到同一个点。改为
   **dst 的 4 个槽位竖排**（A/B/C/D 纵向），每条连线指向自己 rank 对应的那个槽位
   （rank1→B槽、rank2→C槽、rank3→D槽），终点 = 槽位右边缘外侧 4px，箭头尖端正好贴住色块。
   实测垂直偏差 dy=0.0。
5. **虚线恒定**：原代码传输完成后 `stroke-dasharray='none'` → 变成实线。改为全程保持虚线
   （静止 `8 7`、传输中 `9 7` + dashoffset 流动、完成后 `8 7` + 降低透明度）。
6. **层级修正**：SVG 图层顺序改为 `lCards → lChips → lWires → lFx`，
   否则连线上的箭头会被槽位色块压住看不见。

**本轮踩的坑**
- SVG `preserveAspectRatio="xMidYMid meet"`：viewBox 比例与容器比例不一致时必然留白。
  窄屏想撑满就得让 narrow 的 viewBox 比例贴近竖屏容器（400×600），而不是只调 CSS。
- 箭头 marker 的 `refX` 要等于尖端坐标（8），否则箭头与目标之间有肉眼可见的偏移。

## 第四版：卡片尺寸统一 + 槽位居中 + 箭头指向卡片

**用户反馈**：GPU0/1/2/3 尺寸不一致；ABCD 在 GPU 里没居中；箭头指向 GPU0 内部的 BCD 槽位，改成指向 GPU0 即可。
**约束**：ABCD 移动特效保持现状，不改。

**三项改动**
1. **卡片尺寸统一**：抽出 `L.card = {w, h}`，四张卡共用同一尺寸
   （desktop 210×190 / narrow 150×150），src 卡不再用独立宽高。
2. **槽位居中**：
   - dst 的 4 个槽从竖排改为 **2×2 网格**，整组在标题区下方水平垂直居中
   - 源卡的 1 个槽在卡片内水平垂直都居中
   - 槽改为正方形（desktop 44×44 / narrow 32×32），视觉更整
   - dst 徽章从标题下方移到标题右侧（原位置会被槽位遮住）
3. **箭头指向卡片而非内部槽位**：终点改为 GPU0 卡片右边缘外侧 4px，
   三个落点按 `dst.y + dst.h * (0.24 + 0.26*(r-1))` 分布，避免三条线重叠。
   实测终点 x 全部 = 卡片右边缘+4，均在卡片外部。

**验证结论**
- 四卡尺寸：desktop 210×190 ×4、narrow 150×150 ×4 → 完全统一
- 水平偏心：源卡 0.0、dst 网格组中心偏移 0.0
- 箭头：终点均在 GPU0 卡片右边缘外侧，不再进入卡片内部
- 虚线恒定、文字 15 处、无溢出 —— 全部保持

**几何参数集中管理**
```
L = { view, card:{w,h}, dst:{x,y}, src:{x,ys[]}, slot:{sw,sh,gap}, hdr }
```
`hdr` = 标题区高度，槽位区 = `geo.y + hdr` 到 `geo.y + geo.h - 14`，
在此区域内居中。改版时只动 GEO 两个对象即可。

## 第五版：矩形卡片 + 标题条 + ABCD 横排

**用户反馈**：GPU 框是正方的不好看要改矩形；顶部细横条太丑要去掉；标题行填充原细横条颜色、标题靠左；
GPU0 里的 ABCD 要横向排布且居中。
**约束**：箭头、数据块迁移特效保持不变。

**改动**
1. **卡片改矩形**：`card: {w:300, h:152}`（桌面）/ `{w:196, h:108}`（窄屏），宽高比约 2:1。
   因 GPU0 要横排 4 个槽，卡片宽度必须加大。
2. **去掉顶部细横条**：删掉那个 `h:3.5` 的 rect。
3. **标题条**：改用 SVG path 绘制**上圆角矩形**填充原横条颜色
   （dst `#7c3aed` 紫、源卡 `#dfe3ee` 灰）。
   path 用 `A` 弧线命令画两个上角，圆角半径与卡片 rx(14) 一致 —— 用 rect 会切出直角缺口。
   标题文字 `text-anchor: start` 靠左（左边距 16px），dst 标题改白色（紫底），源卡保持灰色。
   dst 徽章移到标题条最右侧（半透明白底 + 白字）。
4. **ABCD 横排**：dst 的 4 槽从 2×2 改为**单行横排**，整组在标题条下方水平垂直居中
   （实测组居中偏差 0.0）。源卡单槽仍居中。

**本轮踩的坑**
- 标题条若用 `<rect>` 画，卡片上方的圆角会被切出直角缺口 → 必须用 path + 弧线命令。
- 窄屏下 GPU0 与 GPU2 水平重叠：dst 右边缘 226 vs src 左边缘 232，只差 6px →
  缩窄卡片（214→196）并把 src.x 从 232 挪到 268，间距提到 62px。
- 改 `hdr`（标题条高度）后卡片内剩余空间变化，卡片高度要同步调整，否则槽位区比例失衡。

**最终几何（第五版）**
```

         slot 46×46 gap12, hdr 34
narrow:  view 480×540,  card 196×108, dst(10,216), src x=268 ys[30,216,402],
         slot 32×32 gap7,  hdr 25
```

## 第十三版：文案改「份」+ 左右各外扩 2%

**用户要求**：日志「各卡各持 1 段」→「每张卡持有 1 份数据」，段改份；
rank0 向左挪 2%，rank1/2/3 向右挪 2%。

**改动**
1. 文案：`每张卡持有 1 份数据`、`目标卡预留 4 份缓冲`（其余「1 号卡发送 B」等不变）
   注意 `<b>` 后不要留空格，否则中文会出现可见间隙。
2. 位置：`dst.x 50 → 21.4`、`src.x 640 → 668.6`（各 28.6 viewBox 单位）

**2% 的换算方法（重要）**
页面百分比 ≠ viewBox 单位。必须先求 SVG 的实际渲染缩放比：
```
s = (最右卡右边缘px − 最左卡左边缘px) / (对应 viewBox 坐标差)
  = (1163.5 − 266.4) / (940 − 50) ≈ 1.008
```
则「页面 2%」= `视口宽 × 0.02 / s` = `1440 × 0.02 / 1.008 ≈ 28.6` 单位。

**关键：不能靠扩大 viewBox 来挪位置**
内容居中时，把 viewBox 左右各加 d、内容也各加 d，屏幕位置恒不变（居中的抵消效应）。
所以只能改内容相对 viewBox 的坐标。

**实测结果（1440×900）**
| | 改前 | 改后 |
|---|---|---|
| 最左卡左边缘 | 18.5% | **16.5%** |
| 最右卡右边缘 | 80.8% | **82.8%** |
| 总跨度 | 62.4% | **66.4%** |

1920/1280 下因缩放比不同，实际偏移约 ±1.9%（固定 viewBox 位移，非固定百分比）。

窄屏未动：narrow 的 dst.x=6、src 右边缘距 viewBox 边界仅 8 单位，已无可外扩空间。

**用户要求**：左上角（rank0 上方）加一个图示，说明「一整份数据由 ABCD 组成」，**不要文字，只要图**。

**设计：一条连续彩条被均分为四段**

- 四个色段紧邻拼接，段间 2px 白线，**外轮廓统一圆角 + 细描边**
- 位置：`x = dst.x`（与 rank0 左对齐）、`y = src.ys[0]`（与 rank1 顶对齐）
- 字母 A/B/C/D 白色居中，字号 `h*0.38`

选这个形态而非「4 个独立圆角块 + 外框」：连续条整体感更强，
一眼读出「一个东西被分成四段」，而散落的独立块更像是「四份」而非「一份」。

**实现要点**
- 用 `clipPath`（圆角矩形）裁切四个色块 → 只外轮廓有圆角，内部分段边缘平直
- 在 `lBg` 层绘制（在卡片之下，但两者不重叠），静态、不参与动画

**踩的坑：`const` TDZ 导致整个舞台空白**
图例代码里 `el('clipPath', {...}, defs)` 用到了 `defs`，
而 `const defs = svg.querySelector('defs')` 写在其**后面** → TDZ ReferenceError →
`buildStage()` 抛异常 → 卡片/连线/字幕全没渲染，页面只剩网格和空控制条。
**修法**：把 `const defs` 提到 `buildStage()` 顶部（清空图层之后）。

教训：往大函数里插新代码块时，务必确认引用的变量在**执行顺序**上已经声明，
`const/let` 不会像 `var` 那样给出 undefined，而是直接抛错且静默失败（页面白屏）。
遇到「整页空白」先查 `Runtime.exceptionThrown`，不要先怀疑 CSS。

**验证**：桌面图例 193×46 @ (21.4, 50)；窄屏 104×25 @ (6, 40)；
无运行时异常，卡片位置与动画均未受影响。

### 补充：聚焦范围扩展到飞行包与链路

用户发现「悬停 D 时虚线上飞行的 B 还有颜色」。三处一起纳入：
- 数据包 `g.pkt` 加 `data-l`（fill 变灰，opacity 仍由 JS 控制）
- 链路 `path.wire` 加 `data-l`，CSS 覆盖 `stroke`
- 箭头 `path.arw`（在 `defs` 的 marker 内）加 `data-l`，CSS 覆盖 `fill`

**关键约束：CSS 的 opacity 规则必须排除 `.pkt` 和 `.wire`**
这两类元素的 opacity 由 `paint()` 逐帧写 attribute（显示/隐藏、active/done）。
CSS 规则的优先级高于 presentation attribute，一旦命中：
① 隐藏的包/线会被强制显示（opacity 被改成 .78）；
② 加在它们身上的 `transition: opacity` 会让出现/消失变滞后。
所以规则统一写成 `[data-l]:not(.pkt):not(.wire)`，只保留它们的 fill/stroke 覆盖。

**另一坑：`querySelectorAll('#stage [data-l]')` 会把 `defs` 里的箭头算进来**
箭头在 `<defs>` 中、DOM 顺序最靠前，按字母筛元素时容易被它抢先命中，
`getBoundingClientRect()` 返回 0 尺寸 → 点击坐标落在 (0,0) → hover 测不出来。
定位图例块要用 `.whole g[data-l=D]` 这种明确路径。

**实测**：悬停 D 时链路 B/C 的 stroke 与箭头 fill 均变为 rgb(204,210,224)，
链路 D 保持自身状态；移开后 B 恢复 rgb(8,145,178)；包 C/D 的 opacity 仍为 0（未被误显示）。

## 第二十五版：修「点进度条，填充没落在鼠标位置」

**根因**：分段条 6 段**等宽**，但每步的时间区间**不等长**
（0.10 / 0.10 / 0.18 / 0.18 / 0.18 / 0.26）。原生 range 是线性的，
点击位置 → 线性时间 → 再按「段内比例」渲染填充，两次换算不同源，于是错位。
例：点条宽 50% 得 t=0.5，落在第 4 段（0.38~0.56）的 67% 处，
填充边界实际出现在条宽 61% —— 肉眼可见差 11%。

**修法**：在 range 与时间之间加一层互逆换算
- `tToV(t)`：时间 → 视觉位置（定位第几段 + 段内比例）
- `vToT(v)`：视觉位置 → 时间（同上反向）
- `paint()` 里 `sc.value = tToV(t)*1000`；input 监听里 `seek(vToT(v/1000))`

于是滑块、填充、鼠标三者统一，点哪填哪。

**实测**：点 12/30/50/68/85% 五处，填充边界与点击点差 -3.0~+3.8px（条宽 1200）；
拖拽 30%→70% 差 2.5px；两端 0.2%→t=1、99.8%→t=999。
残余误差来自段间 5px gap（点落缝里会吸附到段边界），量级 0.3%，可忽略。

**测试注意**：`box.x + box.w` 是 rect 的排他右边界，用它当点击坐标会落到元素外
（表现为 t 不变，容易误判成边界 bug）——测最右端要用 0.998。

## 第三十版：修「落位放大动画只有第一轮生效」

**症状**：刷新后第一遍播放，数据块落地有放大弹跳；循环第二遍起就没有了。

**根因**：重放 CSS 动画的标准做法是 `removeClass → 强制回流 → addClass`，
但原代码写的是 `void s.g.offsetWidth` —— **SVG 元素没有 offsetWidth**（是 undefined），
这行等于空操作，浏览器把"删-加"合并成同一次样式计算，认为 class 没变 → 动画不重启。
第一轮能用，只是因为 class 从无到有。

**修法**：改用 `void s.g.getBoundingClientRect()`（对 SVG 元素有效，会强制刷新样式与布局）。

**验证**：连续三轮 seek 跨越 B 的落地时刻（250 → 520），每轮都在动画启动 90ms 后采样：
`transform` 分别是 1.117 / 1.024 / 1.024，`getAnimations()` 均为 1 个且 `playState=running`。

**同类坑**：在 SVG 里做「强制重排重启动画」时，`offsetWidth / offsetHeight / clientWidth`
全部不可用，要用 `getBoundingClientRect()` 或 `getBBox()`。

- 悬停 B：置灰卡片 2、3；窄屏 380×720 无溢出

## 第三十三版：去掉落位涟漪环

`assets/cv/kit.js` 顶部加开关 **`CV.SHOW_RING = false`**，`spawnPulse` 里涟漪环

## 第三十四版：scatter 目标槽补上「···」传输占位

**问题**：gather 目标卡在数据飞行途中会显示紫色「···」占位框，scatter 没有 ——
目标槽在整个传输期间一直是普通虚线空位，看不出「这一格正在被写入」。

**改法**（`assets/scatter.js` paint 目标卡段，唯一一处）：
```js
var f = flowOf(d.r);
var inFlight = t >= f.start && t < f.end;
var got = t >= f.end;
CV.setSlot(chips[d.r][0], got ? d : null, {
  active: inFlight,                 // ← 新增：复用 kit 的 active 分支（紫底 #f3eeff + 紫边 + ···）
  hidden: t < ROUTE.readyAt
});
```
`CV.setSlot` 的 active 分支本来就有，gather 通过 `i === slotOfRank[activeRank]` 用上，
scatter 只是没传这个参数。所以只改一处调用，kit 与 CSS 都没动。

**实测**（1440×900）
- t≈0.15：三个目标槽都是普通空位 `rgb(247,248,252)`
- t≈0.49（C 在飞）：目标1 = `B`、**目标2 = `···` / `rgb(243,238,255)`**、目标3 = 空
- t≈0.67（D 在飞）：目标3 = `···`
- t≈1：B / C / D 全部落位
- gather 同时刻目标槽 `A B ··· 空`，两页占位样式一致

**仍未对齐的一处**（用户未要求，留着）：gather 在发送期间会把源卡整体压暗
（`opacity .6`），scatter 里源卡 rank0 发送时没有压暗。
