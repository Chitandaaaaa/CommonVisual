# 2026-11-09 · gallery.html 徽章回到真实尺寸 · 4.x 换真实卡片

## 做了什么
1. **3.1–3.4 徽章样片恢复 1:1**：`strip()` 原来用 `TILE(grid,130,52)`，而 `.tile svg{width:100%}` 会把它拉到列宽（685px 列 ≈ 2.6 倍），徽章看着巨大。改成自己建 tile、给 svg 内联 `width:130px`，并把这几节的网格收到 `minmax(170px,1fr)`。实测徽章渲染 = 28（src）/ 30（dst）/ 36（进度·标注）× 18，与文档标注一致。
2. **4.1–4.8 的 `cardStub` 占位矩形全部换成 `cardG` 真实单排卡**（300×170、标题栏、四格）。画布统一 800 宽，卡位 (10,y) / (490,y)；卡距取舞台真实值：横向 180（`grdtDx 480 − 卡宽 300`）、纵向 160（`grdtDy 330 − 卡高 170`）。4.6/4.7/4.8 的连线态演示同样换卡。
3. `.grid.wide svg { max-width:800px }`：窗口变宽使列宽 > 800 时画布封顶 1:1，不再二次放大。
4. `cardStub` 的定义移回动画区（第 1、2 章的动画示例仍在用，原先删掉会直接抛错）。

## 判据
「样片按 viewBox 原始像素显示」是组件文档的底线——`width:100%` 只适合本该占满列的整版示意图（如 6.1 的 1130×680 底板），单件样片必须封顶在自身尺寸。同理 4.x 的卡距不能随手取，横向/纵向空当都从 `spec.js` 的网格常量反推。

- 量样片别用 `h3.nextElementSibling`：`SEC()` 在有 note 时会先插 `.note` 再插 `.grid`，要循环走到 `.grid`，否则量到的是说明条（高度 35）。

## 第三轮（同日）· 5.x 拖尾太淡
1. **根因不是数值，是滤镜用错**：画谱的 `fBlur` 把 `feGaussianBlur` + `feFuncA(slope .14)` 直接作用在色块**本体**，alpha 被乘成 0.14，再乘组透明度 0.55 → 实际 0.077。真值 `assets/parts/stage.js` 的 `fTrail` 是 **`feDropShadow`**（std 5 / #2a3352 / .14），只在块外补软影、不动本体不透明度。改成同构 `fTrail` 后实测近层 alpha **0.556**、远层 **0.282**，与文档 0.55 / 0.28 对齐。
2. **整份包的拖尾是整组小块，不是单方块**：真值 `payload.batch` 的 t1/t2 是同一组小块各画一遍（`docs/visual.html` 05 章同样画法，并注明「大半被白底板挡住」）。画谱 5.2/5.3 原来照《组件文档》画 16×16 单方块 → 被 55/101 宽底板完全盖住；且 `fill: colors[0]` 取到的是 `{c,t}` 对象，渲染成**灰块**。现在按 `translate(-24 0) scale(.8)` / `(-46, .6)` 画整组、色值取 `colors[i].c`。
3. **组件文档只登记不改**（2026-11-09 用户纠正）：我一度按「以实现为准」把 5.2.4/5.2.5/5.3.4/5.3.5 与术语表改成「整组小块」，被要求回退——规范稿是上游，改不改由用户评审。**那条「以实现为准」在 AGENTS 里只管参考稿《分布式通信原语详解.md》，不适用于规范稿**（`docs/纲领.md` 5「设计先于实现」、`docs/设计铁律.md` D1）。现在的画法：按文档画单方块，冲突记 `docs/bugs.md` 待评审。
4. **滤镜模糊 4 / 3 是对的**，别改成 5：`迭代轨迹` 记明实现里滤镜挂在缩放后的组上，屏幕实测就是 4（×.8）/ 3（×.6）。画谱直接按最终尺寸画，所以 std 直接取 4 / 3。
5. **画谱单方块 vs 实现的实测差异**（提报证据）：四块款底板 101 → 16 宽拖尾完全被盖住，画面上「四块款没有拖尾」；两块款只露出前缘约 11px。实现（`payload.batch`）与 `visual.html` 05 章画的都是整组 ×0.8 / ×0.6。
