## 上下标基线偏移：规范值错在换算口径（已按用户裁定改具体像素）

- 用户质疑「文档 5.1 / 19.2 是按父级 15 算的，与代码不符」，要求判定「规范对不对 / 实现对不对」，并指出参数应写成固定尺寸。
- 实测（Chrome，`getStartPositionOfChar`）：`dy="0.34em"` 挂在 `font-size:9.3` 的 tspan 上位移 **3.162**；`dy="-1.28em"` 挂在 `7.8` 上 = **-9.984**（相对下标基线），净值 −6.822。**em 按该 tspan 自身 font-size 换算，不按父级**。
- 结论：参数项没问题（下标 9.3 / 上标 7.8 / 字重 600 / 位置块中心），画面也正确（46 块内文字 bbox 高 20.25，上下留白 11.5 / 14.3）；错的是两个数值 —— 5.1 = 0.34×15、19.2 = 1.28×15，都是把 em 当 CSS 的「相对父级」算的。照规范画，上标会飞出色块顶。
- 修法（用户选 B：写死像素）：`组件文档.md` 2.2.2 / 2.3.2 → 下标 `下移 3.2`、上标 `上移 6.8`。取 6.8 而非 10.0 的理由：《术语表》把「上标基线偏移」定义为**相对主文字基线**的位移，6.8 才是那个量；10.0 是 SVG 里 tspan **逐段累计**的 dy（= 3.2 + 6.8），属实现细节。
- 画谱 `gallery.html`：`SCRIPT` 由 `{ .34, 1.28 }`（em 倍数）改为 `{ 3.2, 6.8 }`（46 基准像素），`span()` 的入参从 em 倍数改为像素，上标处写 `-(SCRIPT.sub + SCRIPT.sup)`。实测 Σ 基线 40 → 下标 43.2、上标 33.2，与规范 1:1；46 节 / 136 svg / 零 JS 报错。
