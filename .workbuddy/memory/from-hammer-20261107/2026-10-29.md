## 组件规范新增「多数据错峰间隔」（08 落位 / 09 融合）

用户要求：落位弹跳与融合的参数组里，各再加一个「多个数据之间的间隔」。

**新增两个规范参数**（`kit.js` SCHEMA + `tokens.js` 基线）：
- `08-seat.seatGap` 多块错峰 **0.17s**（= 规范页 08 演示原本写死的 170ms）
- `09-merge.mergeGap` 多列错峰 **0.25s**（= reduce 页原本写死的 GAP）

分组：08 → 耗时 / 节奏；09 → 耗时 / 节奏 / 关键帧 / 特效。

**边界（写进注释与 README）**：同一批内部多个数据怎么错开 = 组件规范（seatGap / mergeGap）；
「到达终点到开始弹跳的落位延迟」「两趟传递之间停多久」仍是页面编排，走原语页齿轮填秒。

**新增 `CV.seatAt(i, base)`**（kit.js）：第 i 个的时刻 = base + i×seatGap。
页面必须逐帧比 sec，**不能**用 setTimeout 排队 —— 进度条能来回拖，定时器拖不回来。

**消费点**：
- `anatomy.js` 08 节：三块依次落位改读 seatGap；标题与 specs 数字随滑杆联动（加 `params.onChange`）。
- `anatomy.js` 09 节：`STEP = .40` → 现取 mergeGap；specs 末尾两句改写（区分规范 vs 编排）。
- `reduce.js`：`GAP` 写死 0.25 → `CV.specVal('mergeGap')`（实测 mergeGap 0.5 时总时长 14.61 → 16.86s）。
- `allreduce.js`：四段原来一齐跳，改按 seatGap 依次到位+弹跳；删掉 `lastParts`，改用 `seen = {}`（onReset 同步改）；徽章跟最后一段走（`minN`）避免提前报数。
- `reducescatter.js`：`segParts` 的升档时刻加错峰；顺手修老 bug —— 退回 1 份时不清 seen，导致拖回开头再播该段再也不弹。
- `allgather.js`：一轮四块同时到，落位按 gi×seatGap 错开（实测 3.5/3.7/3.9/4.1s 依次弹，符合环序 1→3→2→0）。
- `alltoall.js`：下排一次填满四块，改按 seatAt(i, R[r].arrive) 依次落（实测每 0.17s 加一个）。
- gather / scatter / broadcast 的三趟是**串行** step，不是同批，未改（它们的间隔是编排的 hold）。

**验证**：8 原语页全页回归无 JSERR、maxOp=1；09 四列 transform 采样呈阶梯；面板 08/09 各多出一行「多块错峰 0.17s」「多列错峰 0.25s」。

## 默认值改为 0.5s（用户要求）

`seatGap` 0.17 → **0.5**，`mergeGap` 0.25 → **0.5**（SCHEMA def + tokens.js 基线 + 各兜底值 + README 全部同步）。
`mergeGap (0.5) ≥ fuseDur (0.42)` → 融合严格串行，一列折完才下一列 ✓（这是想要的）。

**实测副作用（用户已知并选择「都不改，保持现有时长」）**：四块一批要 1.5s 才落完，
下一趟却更早出发 —— allreduce 3.20 出发 vs 第一批 3.66/4.16 才落；reducescatter 3.26 vs 3.10/3.60；
allgather 5.12 vs 4.52/5.02（差 0.45s）。allreduce / reducescatter 是「第二轮依赖第一轮结果」的算法，
严格说语义有矛盾；用户决定接受，不改时间轴。**别自行动手加长这三页的落位时段。**
唯一时长变化：reduce 14.61 → 16.86s（TM.merge = SEG + 3×GAP，GAP 0.25→0.5 必然 +2.25s）。
