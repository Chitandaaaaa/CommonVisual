## Gather 收尾：到点淡出 / 齿轮保存 / 时序两级分隔

用户报的四件事，根因与结论：

- **「包飞到虚线终点会停一会再消失」= CSS 过渡和逐帧 JS 抢同一个属性。** `stage.css` 里 `.pkt { transition: opacity .25s ease }`，而淡出是 `pktFadeOut` 每帧写 opacity：每帧一次写入都把过渡重新计时，目标值永远追不上 → 实测到点后 **0.6s 内计算值一直停在 1.00**，等目标值归 0 才用 0.25s 塌下去。修法：`.pkt { transition: none }`，入场柔化改到 `placePacket`（前 8% 行程 0→1）。实测改后弧长走到 1 时立刻开始线性淡出（0.51→1.12s 归零）。
  - 同一 bug 影响全部 8 页 + anatomy 演示（都走 `pktFadeOut`），改公共层后八页回归：`maxOp=1`、4 张卡、无 JS 异常。
- **齿轮其实一直有存（localStorage），只是「存了」看不见，且没有回灌路径**，所以「复制配置」纯属死路（复制出来的 JSON 没地方粘）。改成：
  - 新增 `assets/cv/pages.js`（`window.CV_PAGE_DEFAULTS`）作**代码基线**；`CV.pageOvRead` = 基线 ← `CV.pageOvRaw`（localStorage）。`CV.pageOvRaw` 只读本机改动，写回时不再把基线复制进 localStorage。

## All-Reduce 动画修错：每卡必须 4 格，不是 1 格

用户质疑：「第 1 步 rank0/rank1 互换 A 和 B 像是 A+B，第 2 步又像 (A+B)+(C+D)，不对吧？」

- **根因不是算法，是起点的渲染粒度。** `layout.js` 与 README 的设计决策都写明：reduce / all-reduce / reduce-scatter 的「通信前」必须是**每卡一整份 `[A B C D]`**（各卡 1 片那是 all-gather 的起点，不同位置的数据相加没有意义）。但 `allreduce.js` 给每卡只画了 1 个格子 + 1 个 Σ —— 读起来就是「四卡各持一片、并成一个总和」。
- **算法骨架没动**：仍是 recursive doubling 两轮（横向 0↔1/2↔3，纵向 0↔2/1↔3），README 那条「和 reduce-scatter 是同一张网格的正反两面：份数 1→2→4 vs 段数 4→2→1」依然成立。改的只是每卡从 1 格改成 4 格（`assets/reducescatter.js` 同款画法）。
- 具体改动：
  - `assets/allreduce.js`：`chips[r]` 由单槽改成 4 槽数组；徽章文案由 `1/4` 改成 `1 份 / 2 份 / 4 份`（原来会和 all-gather 的「1/4 段」混淆）；包由 `drawPacket` 改成 `drawPacketBatch`（四段一排）；1/2 份显示段字母并按 `mix(段色, #4c1d95, (n−1)/3)` 加深，4 份显示 Σ 深紫。

## 齿轮推广：broadcast / scatter / all-gather 三页接入 CV.choreo

用户要求「参照 Gather 页面右上角的齿轮，补充广播、分散、全收集」。三页原来都是写死比例（`ROUTE.flows[].start/end` + `duration: 9000` / `TOTAL`），改成与 gather 同一套 `buildTime() → CV.choreo` + `retime` + `CV.gear`。

- **每页三处改动**：① 时序改 `CV.choreo(<page>, segs)`，`ROUTE.flows` 里的 `start/end` 换成 `w: W.<id>`；② `CV.primitive` 加 `retime` 回调；③ 末尾 `mount.getCh + CV.gear({page, name, getCh, onChange: mount.reload})`。HTML 补 `pages.js`（primitive **之前**）与 `gear.js`（primitive 之后）。
