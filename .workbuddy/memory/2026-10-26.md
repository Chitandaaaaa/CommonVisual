## 累加器的颜色 = 份数

```
colorFor(r, n) = CV.mix(DATA[r].color, DEEP, (n-1)/(PARTS-1))
DEEP = '#4c1d95'
```

1 份 = 自己那段原色（块里显示字母 A/B/C/D）→ 2 份 = 掺 1/3 深紫（显示 Σ）→
4 份 = 纯深紫。**终态四张卡颜色完全一致，这就是 All-Reduce 的语义**，
比画一堆箭头说「大家都一样」有力得多。

份数变了才改 `fill`（`lastParts` 守卫），让 CSS 的 fill 过渡自己渐变。

## 踩的坑：双向交换的「法向偏移」符号被抵消

同一条边上两个包对向而行，想让它们各走一条车道，就给路径加法向偏移：

```js
nx = -dy / len * off;  ny = dx / len * off;
```

第一版写的是
```js
var off = (f.from < f.to ? 1 : -1) * (q === 0 ? HUMP : -HUMP);   // ❌
```

结果两个包**永远叠在同一侧**。原因：`dx/dy` 本身已经带行进方向，
B→A 的 `dx` 与 A→B 相反，再乘一个负 `off`，两次取反互相抵消。

正确写法就是两个方向都用同一个正值：

```js
var off = HUMP;    // 法向符号由行进方向自动反转
```

另外 `HUMP = 6` 也不够 —— 包主体 24px（外发光后视觉 ~30），
两侧各偏 6 只有 12px 间距，飞行到中点仍糊成一团。现在 `HUMP = 22`。

**这是「两包重叠」类问题的通用结论：先检查偏移的符号基准是「边」还是「方向」。**

## 验证方式

CDP 截图 + 分段进度条的坑：**scrub 值不是线性时间**。
`vToT` 按 STEPS 段数等分，所以「第 1 轮飞行中点」不在 v=250（那是段边界，正好是起点），
而在 v≈310。想截动画中间态必须先算：

```
sec → t = sec/TOTAL → 找到所属段 k → r=(t-s)/(e-s) → scrub = (k+r)/n * 1000
```

另外截「终态」这类有 CSS 过渡的画面，`@delay` 要给足（≥800ms），
否则会截到 fill / opacity 的中间态，看起来像 bug。

| 原语 | pre | post |
|---|---|---|

## 2026-10-26 补：用户问「All-Gather 写的是拼接并广播，为什么动效是个环」

这是个概念问题，答案分两层：

- **语义（what）**：All-Gather 的输出定义 = 所有卡输入的拼接。不规定怎么实现。
- **算法（how）**：gather+broadcast（两步）／**ring（N−1 轮，NCCL 默认）**／recursive doubling（log N 轮）。
  页面画的是 ring，对照表写的是语义 —— 所以两者不矛盾。

**用户说「环运行 4 次」是数错了**：实际 3 轮（N−1），第 r 轮结束每卡持 r+1 段。
抄 allgather.js 的话术时保持一致，不要跟着写成 4 轮。

**为什么不用 gather+broadcast**（用于以后解释）：
- 总流量一样都是 (N−1)S，但 6 份压在 rank0 一条链路上 → 关键路径 `2(N−1)S/N` vs ring 的 `(N−1)S/N`，**慢一倍**
- star 型有 root，root 挂了全局崩；ring 无 root
- 画的条形对比图：A 组 rank0=6 其余=2，B 组全是 3

**顺手改了两处动作词**（`assets/layout.js` 的 `act`）：
- All-Gather：`拼接并广播` → **`各自拼齐全份`**
- All-Reduce：`相加并广播` → **`互换并累加`**

原因：**「广播」暗含有一个源**，而 all-gather 四张卡地位平等、没有源；all-reduce 的真实实现是
边交换边累加，不存在「先加完再发」这个阶段。动作词写了不存在的阶段，就是在骗读者。

## Reduce-Scatter / All-to-All 动画页：方案已定，尚未落码

用户问「动态实现计划怎么实现，画个草图」，画了两张分镜图，方案如下。

**Reduce-Scatter 用 ring（NCCL 默认），不用递归减半**
- 起手四卡各持整份 4 段 → 3 轮（N−1）→ 每卡只剩 1 段深紫 Σ
- 每轮：发一段给下一家、收上一家的一段、折进累加器 → 段数递减 4→3→2→1
- 视觉沿用 allreduce 那套：2×2 网格 + 顺时针环、`CV.setSlot` 第三态（虚线空位）
  表达「消耗」，颜色 `CV.mix(原色, #4c1d95, ...)` 加深，徽章 n/4
- 卡片高度**不缩**（缩卡要 resizeCard 全重算，代价大且会抖），只把槽位逐轮变空
- 5 段进度条：开场 / 3 轮 / 终态，TOTAL ≈ 7.5s

**All-to-All 用全连接，不压缩**
- 定义本身就是 O(N²) 直连，没有省带宽的算法可挑；12 条消息是它诚实的样子
- 2×2 网格 + 6 条边（4 边 + 2 条**弯曲**对角线，直线会在中心打结）
- 按**目的地**分 4 步，每步 3 条并发（自己那片原地不动），避免 12 条一起飞糊成一团
- 连线/包的颜色跟**源卡**走，不跟目标卡（否则会被误读成「rank1 只收到青色」）
- 5 段进度条，每步 0.9s 飞 + 0.5s 落位，TOTAL ≈ 7.1s

**实现顺序与复用**
1. 先 `reducescatter.js`（可直接抄 allreduce.js：2×2、环、mix 收敛、双车道法向偏移）
2. 再 `alltoall.js`（唯一新东西是对角线几何 + 4 步分组，其余全复用）
3. `relmap.js` 补两条 HREF、更新 REL 表；`home.html` 两个 `node-planned` 改真链接
4. README / layout.html 页脚去掉「暂无动画页」的说明

**待验证的风险点**：对角线两条都在中心交叉，所有包都过中心 → 要么 Q 曲线控制点各偏
40px 绕开，要么中心留白；12 条边里只有当前步的 3 条着色，其余退灰虚线。
`alltoall` 每卡 4 槽的落位映射是「第 j 槽收第 j 步来的片」，槽位固定不重排。
