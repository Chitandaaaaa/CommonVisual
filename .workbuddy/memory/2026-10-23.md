# 2026-10-23 · CommonVisual

## 第三十五版：新增 Broadcast 页面（1→N，复制整份）

**新文件**：`broadcast.html`（复制 scatter.html 改标题/aria/脚本）+ `assets/broadcast.js`。

**与 scatter 的本质差别**
- scatter 是**拆分**：一份拆成 4 段，每卡拿 1 段 → 每卡 1 槽
- broadcast 是**复制**：整份复制给每卡，源卡自己不丢 → **每卡 4 槽（共 16 个槽）**
- 所以四张卡完全同构，卡片尺寸也不用区分源/目标

**几何**：沿用 scatter 的坐标（source x=10 y=255；target x=820 ys[50,255,460]），
只是每张卡都横排 4 槽（46×46 gap12，总宽 220，卡片 300 内居中）。

**整份数据包 `drawBatch()`**（broadcast.js 本地函数，不进 kit）
- 结构对齐 `CV.drawPacket` 的 `{g, head, t1, t2}`，可直接交给 `CV.placePacket`
- 主体 = 白色圆角底板（`fGlow` 阴影）+ 4 个迷你色块
- 拖尾 2 层只画色块不画底板，否则白底叠加会糊成一片
- 尺寸按 slot 比例取：`mw = sw*0.40`、`mh = sh*0.58`、`gap = gap*0.25`
  （初版 0.30/0.40 偏小，飞起来不够显眼，已放大）

**连线统一用源色（紫）—— 这是一个必要的修正**
初版按目标卡分色（青/绿/橙），跑出来发现青线→rank1、绿线→rank2、橙线→rank3
恰好等于 B/C/D 的颜色，极易被误读成「rank1 只收到 B」。
broadcast 三条流运的是同一份数据，所以全部用 `DATA[ROUTE.source].color`。

**kit 的通用增强**（向后兼容）
`CV.drawWire(parent, o)` 与 `CV.drawMarker(defs, id, letter)` 的 `letter` 改为可省略：
省略时不写 `data-l`。原因：`CV.el` 会 `setAttribute(k, undefined)` 写成字符串
"undefined"，不能靠传 undefined 绕过。整份包不对应单一字母，若带 `data-l`
会在悬停聚焦时被错误灰化。

**focus 的语义**
`keepCards: () => RANKS` —— 每张卡最终都持有全部四段，所以悬停任何字母时
四张卡都该保留。实测悬停 A：置灰卡片 0 个、灰块 15 个（16 块里除 A 外的全部），
四张卡的 A 同时亮起 —— 这个效果在 broadcast 里特别有说服力。

**时间轴 / 文案**
```
0.00  rank0 持有整份 [A][B][C][D]
0.10  rank1 rank2 rank3 接收位就绪
0.20  rank0 广播整份给 rank1
0.38  rank0 广播整份给 rank2
0.56  rank0 广播整份给 rank3
0.74  四张卡各持整份 [A][B][C][D]
```

**实测**（1440×900 / 390×844）
- 结构：4 卡 / **16 槽** / 3 线 / 3 包 / 6 段；角色 `0:src 1:dst 2:dst 3:dst`
- t=0：只有 r0 有 [A B C D]，其余三卡的槽 `hidden`（opacity 0）
- t≈0.15：三卡各亮出 4 个空位
- t≈0.49：r1 已收齐，r2 四格全部 `···` 占位，r3 还是空位
- t≈0.67：r3 四格 `···`
- t≈1：四卡全部 [A B C D]
- 落位弹跳 4/4 同时触发，第二轮重放正常，无涟漪环
- 窄屏 viewBox 380×720，无横向溢出

**回归**：gather / scatter 的 `.wire` 与 `marker path` 仍带 `data-l=B,C,D`，
槽数仍为 7，完成态 `A B C D B C D` / `A · · · B C D` 未变 —— kit 改动无副作用。

## 第三十六版：整份包改小方块 + 包内块参与聚焦

**① 形状**（用户给了截图：原来的包是 4 个竖长药丸）
- `mw = mh = round(slot.sw * 0.44)` → 桌面 20×20、窄屏 11×11，**正方形**
- `rx = round(m * 0.25)` → 5 / 3，与 gather 单段包（24×24 rx6.5，27%）同一套比例
- 白底板 `pad = round(m * 0.30)`，`rx = 高 * 0.32`
- 实测 20×20 rx5，白底板屏幕 102×32

**② 包内块参与悬停聚焦**（用户说「悬浮特效这里没有跟随」）
原来整份包没有 `data-l`（它不是单一字母），所以悬停时完全不反应。
现在**每个 mini 块各自包一层 `<g data-l="A">`**，三层（主体 + 两层拖尾）都包。
现有 CSS 规则 `[data-focus="X"] [data-l]:not([data-l="X"]) rect { fill: #e4e8f0 }`
直接命中，不用改样式。
实测悬停 C：pack 内 `A=灰 B=灰 C=rgb(5,150,105) D=灰`，三层全部跟随。

**③ 连带修的：包起步压住源卡**
整份包半宽约 50 单位，若中心停在路径起点，左半会盖住 rank0 的 D 块
（放大截图里能看到橙色块被压掉一角）。
修法：`lead = min(0.32, pkt.half / wire.len)`，让 e 从 lead 起算到 1。
`drawBatch` 因此多返回一个 `half`。宽窄屏按实际路径长度自适应：
桌面 lead≈0.065、窄屏 0.32（窄屏 span 只有 ~74 单位，包几乎占满整条线 ——
这是窄屏固有比例，可接受）。

**验证**：播放/循环正常；落位 4/4 弹跳、无环、第二轮可重放；
gather / scatter 的线仍带 data-l、槽仍 7、完成态未变。

## 第三十八版：点击数据块「钉住」聚焦

**需求**（用户口述）：点击 A → 其他灰；此时悬停 B 显示 B；鼠标移走回到 A；再点 A 取消、点别的改钉。

**实现**（`assets/cv/focus.js` 整体重写，约 90 行）
```
hover   = 指针当前指向的字母
pinned  = 被点击钉住的字母
active() = hover || pinned     ← 唯一的真相来源
```
- `pointerover` 更新 hover → render()
- `pointerleave` 清 hover → render()
- `click`：命中 `[data-l]` 时 `pinned = (pinned === l ? '' : l)` → render(true)
- render 里用 `applied` 记上次写入的值，避免每帧重写 DOM；
  但 `data-pinned` 每次都写（它和 data-focus 不是一一对应）

**边界决策**
- 点舞台空白**不**取消钉住（用户只说了「再点 A 取消」，不额外扩展行为）
- 钉住时给块加描边的方案试过又撤了：描边压在满色块内缘很脏，且会命中
  包里同一字母的 3 层（主体 + 2 拖尾）。改为只加 `cursor: pointer` 做可发现性。

**实测（13 步交互序列，gather，1440×900）**
| 步骤 | focus | pinned |
|---|---|---|
| 悬停 A | A | — |
| 点 A | A | A |
| 移空白 | **A** | A |
| 悬停 B | **B** | A |
| 移空白 | **A** | A |
| 再点 A | A | — |
| 移空白 | 无 | — |
| 点 B → 移空白 | B | B |
| 直接点 A → 移空白 | A | A |
| 点舞台空白 | A（不变） | A |

三页 + 窄屏全部通过：gather/scatter 钉 B 时 2 张卡置灰，
broadcast 钉 B 时 0 张卡置灰（每张卡都持有 B）——与 `keepCards` 语义一致。

**踩坑**：改了 `focus.js` 后测试完全没反应，`pinned` 一直是空。
原因是 **HTML 里的 `<script src="assets/cv/focus.js">` 是固定 URL，浏览器缓存了旧文件**——
之前给页面 URL 加时间戳只对 html 有效。正确做法是 CDP 里
`Network.enable` + `Network.setCacheDisabled({cacheDisabled:true})`。

## 第三十九版：新增 Reduce 页面（N→1，N 份相加）

**新文件**：`reduce.html` + `assets/reduce.js`。

**语义难点**：gather 是「N 段拼成一份」（数据量膨胀），reduce 是「N 份逐元素相加」
（数据量不变）。所以在「一份 = A B C D 四段」的模型下：
每张卡都持有一整份（4 槽），归约后 rank0 的 4 个槽**还是 4 个**，只是每格变成了「和」。

**「和」怎么表达**（这是本页唯一的新设计）
`sumColor(base, n) = mix(base, '#190d33', 0.19 * (n - 1))`，n = 已归约份数（1~4）。
- n=1 原色；每汇入一份深一档；n=4 时 A 从 `rgb(124,58,237)` → `rgb(69,33,133)`
- 初版系数用 0.13，肉眼几乎看不出差异（只到 88,42,169），提到 0.19 才够明显
- 隐喻：颜色越浓 = 加得越多。配合字幕「rank0 得到 4 份之和」

**复用上的两件事**
1. 把 broadcast 里的本地 `drawBatch()` 提升为 **`CV.drawPacketBatch(parent, slot, items)`**
   （kit 第 150 行），返回 `{g, head, t1, t2, half}`，与 `placePacket` 兼容。
   broadcast.js 因此删掉 52 行，两页共用同一份实现。
2. 连线方向照搬 gather（源卡左边缘 → 目标卡右边缘，三个落点 0.28/0.50/0.72）。

**步骤只有 5 段**（其它三页是 6 段）：归约的叙事是「起始 → 三份依次加入 → 完成」，
天然 5 步。controls 的分段数由 `STEPS.length` 决定，不用改。

**实测（1440×900）**
- 结构：4 卡 / 16 槽 / 3 线 / 3 包 / **5 段**；角色 `0:dst 1:src 2:src 3:src`
- 四张卡从第一帧起都是满的 [A B C D]（归约是读取，不清空源卡）
- 结果卡颜色逐档加深：`t=0 → 124,58,237`；`t≈0.26 → 112,53,215`；
  `t≈0.45 → 100,47,192`；`t=1 → 69,33,133`
- 悬停 A：四张卡全保留（keepCards 返回全部）
- 窄屏 380×720 无溢出

**四页综合回归**：卡 4 / 槽 7·7·16·16 / 线 3 / 段 6·6·6·5；
播放 1s → t≈184；完成态与钉住全部正常；控制台只有 favicon 404。

## 第四十版：Reduce 改成 8 步（飞行 + 消化），目标卡拆两排

**为什么改**：原来的 5 步会让人误读成「rank0 先把 4 份堆起来再压缩」。
真实的 reduce 是**通信与计算同时进行**，rank0 始终只有一个累加器 ——
每飞过来一份就立刻折进去。所以要把「到达」「折进」拆成两个动作。

**语义明确写在 reduce.js 顶部注释里**，以后不要改回堆叠式。

**① 目标卡变高，两排**
| | 桌面 | 窄屏 |
|---|---|---|
| `card`（源卡） | 300×170 | 146×126 |
| `targetCard` | 300×**206** | 146×**140** |
| `target.y` | 237（中心 340 不变） | 290（中心 360 不变） |
| `areaPad / rowGap / calcGap` | 12 / 12 / 10 | 9 / 8 / 7 |

- 上排 = 累加器（常驻，`chips[target]`）
- 下排 = 刚到的整份（`ghost[from]`，画在 `lFx` 层，可自由移动）
- 下排**常设 4 个空槽**（画在 `lChips`），让人一眼看出「这里预留了接收位」；
  实体块浮在上面，折进去后空位重新露出来

**② 8 步时间轴**（`duration: 10400`，飞行 0.16 / 消化 0.08）
```
0.00 四卡各持整份            0.49 逐段相加，累加到 3 份
0.09 rank1 的整份送往 rank0   0.57 rank3 的整份送往 rank0
0.25 逐段相加，累加到 2 份    0.73 逐段相加，累加到 4 份
0.33 rank2 的整份送往 rank0   0.81 结果只留在 rank0
```
每条 flow = `{from, start, arrive, end}`：`start→arrive` 飞行，`arrive→end` 消化。
`doneParts()` 用 `t >= f.end` 计份数，所以消化期间颜色只做插值、不跳档。

**③ 折进节奏**（`HOLD=0.32, OFFSET=0.10, MERGE=0.38`，都在消化段内归一化）
`mergeE(p, i) = clamp((p - HOLD - i*OFFSET) / MERGE, 0, 1)`
- 前 32% 驻留（让落位弹跳演完），A~D 再依次错开折进去
- 折进 = 上移一行 + 缩到 0.70 + 淡出；累加器同时做颜色插值并 `spawnPulse` 弹一下

**④ 「计算」标签**
- 两排下方的小方牌，文字「计算」，悬停浮出 `sum · avg · max · min`（窄屏 `sum · avg`）
- 显示区间：**第一次折进开始 → 最后一次折进结束**（`t ∈ [0.25, 0.81)`）
  飞行途中不隐藏，否则会闪 3 次；归约结束后收起，因为是「计算中」的指示
- 结构：`.calc-wrap`（JS 控显隐 `data-on`）> `.calc-chip` + `.calc-tip`（CSS hover 控 tip）
- tip 用**深色气泡**（#363b4e），因为它跨在卡片底边上，白底白卡会糊在一起

**⑤ 踩了两个坑**

1. **黑块**：两排数据全渲染成黑色。查 `getComputedStyle` 的 fill 明明是正确颜色。
   真凶是 `CV.mix` 只认 hex，而 `sumColor()` 返回的是 `rgb(...)` ——
   二次混合时 `parseInt('rg', 16)` = NaN → `rgb(NaN,NaN,NaN)` → 黑。
   已让 `CV.mix` 的 `hex()` 先试 `/^rgba?\(/`，兼容自己产出的格式（向后兼容）。

2. **ghost 的黑块/渲染异常**：外层 `.ghost-g` 用 SVG `transform` 做融合位移，
   内层 `.slot-g` 挂 CSS `slot-pop` 动画 —— 两层 transform 叠加时 Chrome 会把
   SVG 分组提成合成层，填充色渲染丢失。
   改法：**弹跳也用 JS 算**（`popOf(q)`，曲线对齐 slotPop 的 0.35→1.16→1），
   与融合位移合并成**一个** transform：
   `translate(cx(1-k), cy(1-k) - rowStep*e) scale(k)`，`k = pop.k * (1-0.30e)`。
   附带好处：拖进度条也能复现弹跳（CSS 动画不能）。
   另外 `.ghost-g` 不要加 `will-change`，同样会渲染成黑块。

3. 隐藏中的 ghost 要 `pointer-events: none`（`.ghost-g[opacity="0"]`），
   否则透明块会截获 hover、误触发聚焦。

**⑥ 连线落点**
三条线不再按整卡高度分布，而是**全部收在第二排的高度带**内
（`baseRatio = rowCenter / dst.h`，步长 `slot.sh*0.42/dst.h`）——
数据确实是奔着那一排去的，落点跟着语义走。

**⑦ 新文档**：`docs/待讨论-Ring与Tree.md`，记录 Star/Ring/Tree 的差别与 5 个待定问题。
关键结论：本页画的是 Star（Direct）reduce，**不是 NCCL 的默认实现**；
Ring 赌带宽（延迟 ∝ N），Tree 赌延迟（∝ log N），NCCL 按消息大小 + 拓扑现场选。

## 第四十一版：Reduce 改 9 步 + 源卡清空 + 卡片长高动画

**用户提的三点**
1. 开场先让 rank0 是「一份数据」的尺寸，再加一步「预留 4 份缓冲」把卡片撑成两排
2. 进度条：传递这一步要**等落位特效走完**才算完成
3. 质疑：「rank123 给完数据，自身还有数据？」——**问对了，是我之前写错了**

**① 语义修正：源卡送完就清空**
reduce 是**消耗**数据的操作，不是复制。源卡交出数据后缓冲区就空了。
（broadcast 才是复制，源卡留着不动；gather/scatter 同样是消耗，但它们的源卡目前仍保留数据，
 属于历史遗留 —— **待用户决定是否一并统一**。）
- 起飞后源卡 4 个槽显示 `···`（`setSlot(s, null, {active:true})`）
- 到达后变成真空槽（虚线框）
- 之前 reduce.js 注释写的「归约是读取，不会清空源卡」是错的，已删

**② 开场两步 + 卡片长高**
`TIME = { init:0.052, prealloc:0.100, fly:0.138, pop:0.052, merge:0.083 }`，`duration: 12000`
```
0.000  四卡各持整份
0.052  rank0 预留 4 份缓冲        ← 卡片从 170 长到 206，下排空槽淡入
0.100  rank1 的整份送往 rank0     ← 传递步含落位弹跳
0.290  逐段相加，累加到 2 份
0.373  rank2 的整份送往 rank0
0.563  逐段相加，累加到 3 份
0.646  rank3 的整份送往 rank0
0.836  逐段相加，累加到 4 份
0.919  结果只留在 rank0
```
- 目标卡的**中心**固定（桌面 cy=340 / 窄屏 cy=360），高度变化时上下同时扩
- 上排数据 y 从「居中」插值到「靠上」：初始 `rel0 = hdr + (card.h-hdr-16-sh)/2`，
  长成后 `rel1 = hdr + areaPad`
- 下排空槽（`emptyRow`，画在 lChips）opacity = grow，初始隐藏
- 连线每帧重算（`layoutWires`），落点跟着第二排走
- 计算标签改成**局部坐标 + 每帧 transform 定位**，才能跟着卡片走

**③ 进度条时机**
「传递」这一步的段落 = `[start, arrive + pop)`，即**飞行 + 落位弹跳**都算在这一步里，
特效没走完进度条就不满。消化步 = `[arrive+pop, end)`。
- 消化归一化改为以 `arrive+pop` 为起点：`p = (t - arrive - pop) / (end - arrive - pop)`
- `mergeE(p,i) = clamp((p - i*0.15) / 0.55, 0, 1)` → A:0~0.55 B:0.15~0.70 C:0.30~0.85 D:0.45~1.0
- 原来的 `HOLD`（等弹跳演完的驻留）可以去掉了，弹跳已经归到上一步

**④ kit 新增 `CV.resizeCard(card, geo)`**
卡片尺寸变化时，白底矩形、彩色标题条、标题文字、角色徽章都要跟着重画。
- `drawCard` 的返回值补了 `radius / hdr / role / badgeSize`

## 第四十二版：修 reduce 的两个布局 bug

**① 开场三条虚线箭头没对齐（落在卡片外）**
- 原因：`layoutWires(rowY2 + sh/2)` 用的是**第二排**的高度带，
  但开场时卡片还没长高（grow=0），第二排根本不存在 ——
  实测落点 y = 389/408/427，而卡片底边只到 425，**两个箭头挂在卡片外面**。
- 修法：落点中心随卡片长高在「第一排 → 第二排」之间插值
  `landY = (rowY + sh/2) + rowStep * grow`，
  这样开场时三个箭头正对 rank0 里的数据，长成两排后自然滑到下排。
- 三条落点仍按 `step = slot.sh * 0.42` 上下错开，保持错位感。

**② 「计算」方牌没左右居中**
- 原因：方牌在**局部坐标**里是以原点为中心画的（`x = -o.w/2`），
  但 translate 用的是 `tGeo.x + (tGeo.w - calc.w)/2`（= 108），
  等于多偏了半个身位（w/2 = 52）。**方牌局部坐标已居中时，平移就该用卡片中心**。
- 修法：`translate(tGeo.x + tGeo.w / 2)`（= 160）。
- 这类 bug 的通用教训：**局部坐标已含居中偏移时，
  外层平移量不要再减一次自身宽度**。

**实测**：t=0 三个箭头落点 y=330/350/369（卡片内，正对数据行）；
计算方牌中心 160 = 卡片中心；窄屏同样正常。

## 第四十三版：Reduce 布局重构（居中 + 计算方框独立位置 + 间隔 +0.1s）

**用户三点要求**
1. 第二步「预留缓冲」后，rank0 里两份数据**上下左右居中**，且**不预留**计算方块的位置
2. 第 4 步（消化步）：先上下拉宽 rank0 → 展示计算方框 → 进行计算 → 算完方框消失、卡片收窄
3. 计算时 ABCD 融合间隔 **+0.1s**

**① 几何重写：卡片顶边固定，中心不再固定**
原来 `cardTop = cy - h/2`（中心固定），导致卡片长高时数据块整体上下漂移。
改成**顶边固定、内容从顶边往下推**：
```
h1 = hdr + areaPad*2 + sh              一份数据
h2 = h1 + sh + rowGap                  两份数据（不含方框位置）
h3 = h2 + calcGap + calc.h + areaPad   计算中
第一排   = 顶边 + hdr + areaPad
第二排   = 第一排 + rowStep
计算方框 = 第二排 + sh + calcGap
```
- 两排数据在卡片里上下居中（上下留白各 areaPad）、左右居中（totalW 居中）
- 计算方框永远卡在第二排下面，卡片多高都不挤
- **数据块位置全程是常量** —— 融合过程中一点不漂

**② 时间轴改成「秒」为单位**
`T = {init:0.6, prealloc:0.7, fly:1.7, pop:0.6, grow:0.4, merge:1.3, shrink:0.4}`
`CYCLE = fly+pop+grow+merge+shrink = 4.4`，`TOTAL = 15.0s`
每份分四拍：飞 → 落位弹跳 → **拉宽出方框** → 融合 → 收窄。
STEPS 的 t 用 `N(sec) = sec / TOTAL` 归一化。

**③ 间隔 +0.1s**
旧：`mergeE(p,i) = clamp((p - i*0.15)/0.55, 0, 1)`，p 是归一化进度 → 实际间隔 0.15×1.0s = 0.15s
新：`mergeE(p,i) = clamp((p*T.merge - i*GAP)/SEG, 0, 1)`，`GAP=0.25s`、`SEG=0.55s`
→ 间隔 0.15s → **0.25s（正好 +0.1s）**，单段时长不变。

**④ CSS 坑：`.calc-wrap` 的 opacity 过渡会和逐帧插值打架**
原来靠 `data-on` + CSS `transition: opacity .28s` 切换显隐。
现在卡片高度是连续插值的，方框要在拉宽/收窄过程中渐隐渐现，
所以改成 **JS 直接写 `style.opacity`**，并把 CSS 的 transition 去掉
（JS 里也加了 `g.style.transition='none'` 兜底）。

**⑤ 连线落点重排**
三条线原来挤在第二排的窄带里（step = sh*0.42），视觉上像一条。
改成沿目标卡右缘按高度比例分散：`ty = cardTop + cardH * (0.30 + 0.20 * k)`，
和 gather 的做法一致。卡片长高时落点跟着走，始终落在卡片范围内。

**实测（1440×900 / 390×844）**
- 9 段进度条；t=0 rank0 只有一行
- 预留步结束：卡片两排数据居中，下排 4 个虚线空位
- 消化步：卡片拉宽 → 「计算」方框出现在第二排下方 → 融合 → 方框淡出、卡片收窄
- 终态：三张源卡全空，rank0 上排深色、下排空位、卡片恢复两排高度
- gather / scatter / broadcast 回归无变化

用户要求：① 第一步初始态 rank0 卡片大小、数据块位置与源卡一致；

**④⑤ 接收位补「···」等待态（用户反馈「接收数据块的状态不对，我记得是3个点什么的」）**

用户记得 gather 里目标卡的接收位在传输窗口内显示「···」，而 reduce 的第二排
从头到尾都是空虚线框，缺了这一档。

实现（paint 里）：`CV.setSlot(s, null, { active: waiting })`，`waiting` =
「还有份要收」（sec < 最后一份的 mergeEnd）。空位在 chips 层、ghost 在 fx 层，
所以数据落位时彩色块天然盖住「···」；融合折进上排后又露出「···」（这格空了，在等下一份）；
全部归约完成后 waiting=false，恢复成空虚线框。

**槽位三态语言（`CV.setSlot`，四页共用）**：
① 有数据 = 实心彩色块 + 白字母；② 传输中/待命 = 浅紫底 + 紫色实线 + **「···」**；
③ 空 = 浅灰底 + 虚线框 + 无字。

**④⑥ 落位弹跳对齐 gather（用户反馈「接收完数据有放大跳动特效，明显不一样」）**

关键事实：gather 的落位弹跳是 CSS `.slot-pop`：
`animation: slotPop .55s cubic-bezier(.2,.9,.3,1.45)`，
关键帧 `0% scale(.35) → 55% scale(1.16) → 100% scale(1)`。

**因为 y 控制点 1.45 > 1，曲线会过冲，实际峰值是 1.28 而不是 1.16** ——
「啪」一下的弹性感就来自这里。之前 reduce 用手写的 easeOutQuad 近似，
峰值只有 1.16 且是软减速，所以看着明显"软"、不像 gather。

改法：
- `assets/cv/dom.js` 新增 `CV.cubicBezier(x1,y1,x2,y2)`（牛顿迭代 8 次 + 二分兜底），
  在 JS 里原样复刻 CSS 曲线
- reduce 的 `popOf` 改用 `POP_EASE = CV.cubicBezier(.2,.9,.3,1.45)`，
  按 CSS 的方式分两段（0→55%、55%→100%，每段各自套这条缓动）
- **opacity 要自己 clamp 到 1**（CSS 会把 opacity 计算值钳进 [0,1]，JS 不会，
  不过冲那段会算出 1.15 的 opacity）

实测两页曲线逐点吻合（ms, scale）：
gather `44:0.899 94:1.184 144:1.280 194:1.284 244:1.239 …`
reduce `54:0.901 116:1.207 178:1.288 241:1.269 …`（reduce 的 T.pop=0.6s 略慢于 CSS 的 0.55s，形状相同）

**为什么落位弹跳不能用 CSS 动画**：ghost 外层要写融合位移的 transform，
内层再挂 CSS 动画 = 两层 transform 嵌套，Chrome 会把 SVG 分组提成合成层、
填充色渲染成黑块（老坑）。所以只能 JS 算，曲线就得自己复刻准。

**④⑦ 计算方框收窄 + 徽章放大（用户反馈）**

- 计算方框左右留白太多：desktop `calc.w` 104 → **56**、narrow 62 → **40**

注：徽章改动在 kit.js，**四个页面同时生效**，已回归 gather/scatter/broadcast。

## All-Gather 尺寸统一（修「卡片和数据块都变大」）

用户反馈：「感觉卡片和左上的数据块都变大了，保持统一尺寸」。

### 根因
**不是**卡片本身画大了，而是 **viewBox 画布比别的页小**：
- 其它四页：view `1130×680`（narrow `380×720`）
- All-Gather 原来：view `850×530`（narrow `380×412`）

SVG 是 `preserveAspectRatio="xMidYMid meet"`，按 min(w/vbW, h/vbH) 等比缩放到容器。
viewBox 越小 → 缩放倍率越大 → 整页内容都变大。
实测原来 allgather 的 cardPx 是 303×172？不对 —— 改之前是 **385×192**（比 gather 的 303×172 大 27%）。

### 修法
GEO 直接抄其它页的尺寸，只重排网格：
```js
desktop: { view:{w:1130,h:680}, card:{w:300,h:170}, grid:{x:175,y:136,dx:480,dy:330},
           legendY:17, slot:{sw:46,sh:46,gap:12}, hdr:36, title:15, badge:10 }
narrow:  { view:{w:380,h:720},  card:{w:146,h:126}, grid:{x:8,y:185,dx:218,dy:300},
           legendY:113, slot:{sw:25,sh:25,gap:5},  hdr:28, title:12.5, badge:8.5 }
```
- 槽位落位公式也改成和 gather 目标卡一致：
  `areaY = hdr; areaH = card.h - hdr - 16; y = geo.y + areaY + (areaH - sh)/2`
  （原来不减那个 16，导致数据块在卡里偏高）
- 徽章字号 10.5→10、窄屏 9→8.5（和 gather 对齐）

### 验证
写了个 `/tmp/measure.mjs` 探针，用 `getBoundingClientRect()` 量**渲染像素**：
gather / allgather / reduce 三页现在都是
`cardPx=[303,172] chipPx=[46,46] titlePx=[55,22]` —— 完全一致。

### 教训（写进 MEMORY.md）
**新增原语页时，viewBox / card / slot / 字号必须和其它页逐项抄齐**，
因为 SVG 是等比缩放的，画布大小直接决定视觉大小。改完要用像素探针量一遍，
不要凭 viewBox 数字猜。

### 教训：写 HTML 后跑一遍标签配对校验
```python
from html.parser import HTMLParser

# 遇到 stack[-1] 与 close tag 不一致就报错
```
浏览器对标签不匹配是容错的，**不会报错、只会静默错乱**，

## 首页 v4 · 修「箭头和卡片重叠」

用户截图标注：红框内那段箭头和卡片重叠。

### 根因
`grid-template-rows: repeat(6, auto) repeat(5, 34px)` —— **这个写法本身是错的**。
11 行是**交错**的（节点行 1/3/5/7/9/11，箭头行 2/4/6/8/10），
但 `repeat(6,auto) repeat(5,34px)` 把 auto 放在前 6 行、34px 放在后 5 行，
于是 **row 7（Reduce / All-Reduce）被强行压成 34px**，
而节点卡片实际 64px 高 → 上下各溢出 15px，正好压在 row 6 的箭头上。

### 修法
逐行写死交错行高：
```css
grid-template-rows: auto 34px auto 34px auto 34px auto 34px auto 34px auto;
```

### 教训
**CSS Grid 里 `repeat()` 不能表达交错模式** —— 一律逐行列全。
下次用几何探针（getBoundingClientRect）逐元素核对
「节点 y + h 应恰好等于下一个节点 y」。

### 验证
16 个元素全部无重叠：节点 64px、箭头行 34px，
每个节点 y + 64 + 34 == 下一个节点 y，完全连续。
1440×900 / 390×844 均正常；悬停高亮仍工作。
