## All-Gather 尺寸统一（修「卡片和数据块都变大」）

用户反馈：「感觉卡片和左上的数据块都变大了，保持统一尺寸」。

### 根因
**不是**卡片本身画大了，而是 **viewBox 画布比别的页小**：
- 其它四页：view `1130×680`（narrow `380×720`）
- All-Gather 原来：view `850×530`（narrow `380×412`）

SVG 是 `preserveAspectRatio="xMidYMid meet"`，按 min(w/vbW, h/vbH) 等比缩放到容器。
viewBox 越小 → 缩放倍率越大 → 整页内容都变大。
实测原来 allgather 的 cardPx 是 303×172？不对 —— 改之前是 **385×192**（比 gather 的 303×172 大 27%）。

### 修法
GEO 直接抄其它页的尺寸，只重排网格：
```js
desktop: { view:{w:1130,h:680}, card:{w:300,h:170}, grid:{x:175,y:136,dx:480,dy:330},
           legendY:17, slot:{sw:46,sh:46,gap:12}, hdr:36, title:15, badge:10 }
narrow:  { view:{w:380,h:720},  card:{w:146,h:126}, grid:{x:8,y:185,dx:218,dy:300},
           legendY:113, slot:{sw:25,sh:25,gap:5},  hdr:28, title:12.5, badge:8.5 }
```
- 槽位落位公式也改成和 gather 目标卡一致：
  `areaY = hdr; areaH = card.h - hdr - 16; y = geo.y + areaY + (areaH - sh)/2`
  （原来不减那个 16，导致数据块在卡里偏高）
- 徽章字号 10.5→10、窄屏 9→8.5（和 gather 对齐）

### 验证
写了个 `/tmp/measure.mjs` 探针，用 `getBoundingClientRect()` 量**渲染像素**：
gather / allgather / reduce 三页现在都是
`cardPx=[303,172] chipPx=[46,46] titlePx=[55,22]` —— 完全一致。

### 教训（写进 MEMORY.md）
**新增原语页时，viewBox / card / slot / 字号必须和其它页逐项抄齐**，
因为 SVG 是等比缩放的，画布大小直接决定视觉大小。改完要用像素探针量一遍，
不要凭 viewBox 数字猜。

## 首页 v3 · 修 bug（去眉标 / 去面板外框 / 补箭头 / 修标签不匹配）

3. 右侧三个框有 bug，**箭头没了**

### 根因（都是真 bug，不是样式问题）

**① 箭头消失 —— grid-row:6 是空的**
节点行是奇数（1/3/5/7/9/11），箭头行是偶数（2/4/6/8/10）。
原来只写了 2/4/8/10，**漏了 row 6**，所以

补了 2 条 `conn-v`（col1/row6、col3/row6），共 8 条连线。

**② All-to-All 被包起来 —— HTML 标签不匹配（真凶）**
```html
<div class="node node-planned" id="n-reducescatter"> ... </a>   ← div 开头、a 结尾
```
`n-reducescatter` 和 `n-alltoall` 都是 `<div>` 开头却用 `</a>` 收尾，

写完最好用 HTMLParser 校验一遍标签配对。**

**③ 玻璃面板外框去掉**
`.tree-panel` 只保留 `position:relative` + panelIn 动画，
去掉 padding / border-radius / background / border / box-shadow / backdrop-filter。
现在树直接浮在页面背景上。

**④ 眉标去掉**
删掉 HTML 里的 `.eyebrow` 整段 + CSS 里对应的 `.eyebrow` / `.pulse` 规则。

- **连线动画时序串位**：原来用 `#tree .conn:nth-of-type(n)` 猜顺序，
  但 node 和 conn 混在同一容器，`:nth-of-type` 按标签名计数（`<a>` 和 `<div>` 各算各的），
  计数完全对不上。改成在 HTML 上逐条标 `style="--d:0.400s"`，
  CSS 用 `animation-delay: var(--d, .4s)`。
- **行高写死**：`grid-template-rows: repeat(11, auto)` → `repeat(6, auto) repeat(5, 34px)`，
  箭头行固定 34px，节点行 auto，杜绝相邻内容把行撑爆。
- 给 `.tree > .node` / `.tree > .conn` 加 `align-self: center`。

悬停探针：`n-gather` → 点亮 2 条 gather 线（横向 + 竖向）；
`n-allreduce` → 点亮 `reduce` + `allreduce`。

### 教训：写 HTML 后跑一遍标签配对校验
```python
from html.parser import HTMLParser
VOID={'br','img','input','meta','link','hr','source','path','circle','rect','use',...}
# 遇到 stack[-1] 与 close tag 不一致就报错
```
浏览器对标签不匹配是容错的，**不会报错、只会静默错乱**，
这类 bug 只能靠校验器或几何探针（getBoundingClientRect）发现。

## 首页 v4 · 修「箭头和卡片重叠」

用户截图标注：红框内那段箭头和卡片重叠。

### 根因
`grid-template-rows: repeat(6, auto) repeat(5, 34px)` —— **这个写法本身是错的**。
11 行是**交错**的（节点行 1/3/5/7/9/11，箭头行 2/4/6/8/10），
但 `repeat(6,auto) repeat(5,34px)` 把 auto 放在前 6 行、34px 放在后 5 行，
于是 **row 7（Reduce / All-Reduce）被强行压成 34px**，
而节点卡片实际 64px 高 → 上下各溢出 15px，正好压在 row 6 的箭头上。

### 修法
逐行写死交错行高：
```css
grid-template-rows: auto 34px auto 34px auto 34px auto 34px auto 34px auto;
```

### 教训
**CSS Grid 里 `repeat()` 不能表达交错模式** —— 一律逐行列全。
下次用几何探针（getBoundingClientRect）逐元素核对
「节点 y + h 应恰好等于下一个节点 y」。

### 验证
16 个元素全部无重叠：节点 64px、箭头行 34px，
每个节点 y + 64 + 34 == 下一个节点 y，完全连续。
1440×900 / 390×844 均正常；悬停高亮仍工作。
