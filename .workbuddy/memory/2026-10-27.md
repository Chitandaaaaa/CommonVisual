## 首页原语树：悬停卡片「刷新一次」的 bug 修复

- 现象：鼠标悬浮卡片时，整张卡片像被「刷新」了一遍，观感很差。
- 根因（探针确认）：`.node:hover::before` 触发 `@keyframes sheen` —— 一道 90% 白的高光带每 hover 一次就横扫整张卡片（bTf 从 -382px 扫到 +383px），就是那个「刷新」观感。
- 顺带发现的潜在 bug：`nodeIn` 用了 `animation: ... both` 的 fill，动画结束后仍把 `transform` 锁成 `none`，导致 `.node:hover { transform: translateY(-3px) }` 永远不生效（lift 死掉）。
- 修复（`assets/index.css`）：
  1. 删掉 `.node::before` / `.node:hover::before` / `@keyframes sheen` 整个高光扫光逻辑；
  2. `nodeIn` 的 fill 从 `both` 改成 `backwards`（入场延迟期保持初始态、不闪未样式内容，结束后释放 transform 让 hover lift 生效）。
- 验证：CDP 真实 mouseMoved 悬停后，bAnim="none"、bTf="none"（扫光没了），tf 平滑过渡到 matrix(…0,-3)（lift 复活），opacity 全程为 1（无 is-lit 闪烁）。
- 注：合成 mouseenter 只能触发 JS 的 is-lit，触发不了 CSS :hover，必须用 Input.dispatchMouseEvent 真实移动鼠标才能复现/验证 hover 效果。

## 05 动态改语义：「两个 / 四个」是整份包，不是四条线

用户原话：「数据包，2个，4个，参照图片，**2个就只有ab**，不是现在的4个数据块分开传递」。
所以 tab 里的「两个 / 四个」指的是**一份数据里有几个块**，不是包数：

- 「单个 / 曲线」保持 24×24 单色包（一个 `.pkt`）。
- 「两个」= 一个整份包（白底板 + **A B** 两块）；「四个」= 一个整份包（白底板 + A B C D = 图片）。
- 三处旧代码一起改：去掉 `N` 条线 / `flows` 数组 / 错峰 `.18~.22s`，`drawFly` 现在只画一条线一个包。

实现要点：
- `CV.drawPacketBatch(A, G.desktop.slot, items)` 直接能用，返回 `{g, head, t1, t2, half}`，
  `placePacket` 认这套结构。**`half` 要拿来算线的起止点**：线要从 `SX + half` 画到 `TX - half`，
  否则线会插进包身。半宽 = (n×20 + (n−1)×3)/2 + 6 → 两块 27.5、四块 50.5。
- 源 / 目标画**同尺寸的虚线框**（46 的槽装不下一份），源端常驻一个整份包（复制语义，
  和单色包模式一致：飞行中源端仍然有），落点那个包平时 `opacity 0`、落地才亮并 `spawnPulse`。
- `spawnPulse` 要 slot 对象，整份包没有槽，就传伪 slot `{g: dst.g, cx: TX, cy: CY, w: bw, h: bh}`。
- 整份包的**线保持中性灰** `#8b93a6`：染成 A 的紫会被读成「只传了 A」。单色包仍用自身色。
- `lead`：整份包左缘本来就贴着线起点，`lead = 0.015` 就够；单色包仍是 `min(.16, 18/len)`。

## 07 动态 tab：几何与内容拆成两步（用户点名）

原来的循环是「长高时顺便把内容也换了」，看着分不清是谁在动。改成 8s、八段：

```
②-a 长空间(0.6–1.35) → ②-b 落数据(1.6–1.85) → ③-a 长空间(2.6–3.35) → ③-b 显示计算(3.6–3.95)
收 1 计算先消失(4.9–5.25) → 收 2 数据先退回空槽(5.4–5.65) → 收 3 收方框空间(6.1–6.8) → 收 4 收第二排空间(7.0–7.75)
```

- 第二排透明度 = `seg(g2,.35,.85)`（空间层）× `fade`（内容层）。**内容切换点必须落在 fade=0 的那一帧**
  （1.6s 空槽→实块、5.65s 实块→空槽），否则实数据会突然蹦出来 / 突然没掉。
  回收时 5.65–5.85 再让空槽 `fade` 升回 1，中间那 0.2s 是「什么都没有」，但前一帧本来就近乎全透明，看不出断档。
- ③ 的「先长空间、后填内容」需要一个看得见的空位，加了个同尺寸**虚线占位框** `ph`：
  只在正向 `seg(g3,.55,.85)` 淡入、被 `1-chipOp` 压掉；**`T >= 4.9` 直接锁 0** ——
  回收时若还留着，卡片一缩它就挂到卡底外面去了（截图里抓到的就是这个 bug）。
- 占位框门槛用 `.55~.85` 而不是 `.25~.6`：g3 太小时卡片才 210 出头，框底离卡底只剩 3px，像压线。
- 验证：逐 100ms 采样一次 `h / letters / chipOp / phOp`，八个阶段的先后顺序全对；
  截图复核 7 个关键帧；12 节 / 22 demo / 7 组 tab、1440 与 820 宽 `overflowX = -15`、控制台零报错。

## 05 数据包动态：落点只剩一个虚线框（用户点名）

用户原话：「本质上没有数据块落位弹跳那部分，只有虚线，到虚线终点后，缓慢消失」。四个模式统一改。

- 删掉 `setSlot(dst, …)` / `dst` 整份包 / `spawnPulse`：**落点从头到尾就是一个虚线框**，
  包飞进去之后 `opacity` 1→0 走 0.6s（`FADE`），然后 hold 0.7s 再来一轮。
- **取点路径 ≠ 可见路径**：可见线止于框边（`TX − 框宽/2`），但 `placePacket` 按弧长取点必须走到
  框中心，所以另画一条 `stroke: none` 的 full 路径专门给定位用。
  顺带踩到：`placePacket` 会把 `stroke-dashoffset` 写在它收到的那个 `wire.path` 上 ——
  写在隐藏路径上等于没写，可见线要自己补 `-e*110`。
- 第一版只把 `x1` 改成框边、`placePacket` 还用同一条线，结果整份包停在框**左边**半个包宽的地方
  （因为 batch 的 half = 50.5）—— 截图一眼就看出来了。
- 循环：`DUR 1.5 + FADE .6 + HOLD .7`。整份包源端那份在飞行 + 淡出期间藏起来、hold 段再长回来；
  单色包源槽一直没有 `setSlot(null)`，A 全程在（复制语义）。
- 验证：四模式到达态截图（包都在框中心、半透明淡出）、飞行中/循环间歇截图；
  12 节 / 22 demo / 7 组 tab、1440 与 820 宽 `overflowX = -15`、控制台零报错。

## 09 融合：新设计的一套「上吸」动效（用户点名不要弹跳）

用户原话：「还有个融合的动画，两行数据块，下面的向上面依次融合，这个特效我不想和落位弹跳一样」。
→ 新增**第 09 节**「融合 merge」（在 08 落位弹跳之后，正好把两种手感摆一起对照），
后四节顺延：聚焦 10 / 舞台分层 11 / 两套尺寸 12 / 施工约定 13。

- **新原语 `CV.createMerge(parent, o)`（kit.js）**：`{x, y0, y1, size, data, target, to}`，
  返回 `{apply(p), reset()}`，p ∈ 0~1 由调用方推。图里 5 个实例（动态 4 列 + 静态 4 帧）全调它。
- 和 `slot-pop` 的**本质区别**（写进 specs，别再混）：
  落位 = 无→有，`.35 → 1.29 → 1`，靠**过冲**；融合 = 有→无，位移↑ 缩放↓ 透明度↓，**三个量全单调**，
  目标块自己一点不缩放，只被一道白光扫过。
- 三段：① 唤醒 `0–.16` 只改颜色/描边（块不动）② 上浮 `.16–.72` 走 y₀→y₁ 并缩到 `.36`，
  过半开始淡出 ③ 注入 `.55–1` 白光扫过、`.78` 那一刻目标换 `Σ` 并 `mix(color, DEEP, 1/3)`。
- 白光：与块等大的 rect + 三停渐变（两端全透明），**只改 `gradientTransform` 的 `translate(−1→1)`**，
  不用 clipPath；`stop-opacity` 从 .85 降到 .70 才不糊字。
- 拖尾两块残影 18 / 30、缩放 .8 / .6，**必须按进度开门**：
  `cl((p−.18)/.10) × (1−cl((p−.42)/.20))`。第一版没开门，静止态就在块底下挂两道影子（截图抓到）。
- **踩坑（重要，会害到以后所有缩放动画）**：`stage.css` / `anatomy.css` 里 `.slot-g` 有
  `transform-box: fill-box; transform-origin: center` —— 它**同样作用于 transform 属性**，
  于是 `translate(cx−half·s, …) scale(s)` 变成绕块自身中心，整块偏 `(half−half·s)`，
  飞到最后歪在目标格右下角。修法：`g.style.transformBox='view-box'; g.style.transformOrigin='0 0'`
  （三件套 src/t1/t2 都要盖）。探针复核：四帧中心 x = 100/270/440/610 一分不差。
- 动态节奏：`HOLD0 .55 + 4×STEP .40 + DUR .42`，3.2s 一轮；`T<.06` 调 `reset()`（fresh 标志防重复）。
- 验证：13 节 / 21 demo / 7 组 tab、TOC 13 项与编号一一对应、1440 宽 `scrollWidth-innerWidth = 0`、
  12 个页面逐页 probe 零报错（kit.js 是公共层）。

## 05 动态：去掉终点虚线框，包心落在箭头上

用户：「数据包动态，实际上，完整数据的中心是落在箭头上就慢慢消失了，箭头后面没有框，去掉框。」

- 删掉终点那个 `4 3` 虚线框（整份包与单色包两条分支都删），`x1` 直接取 `TX = 542`。
- 顺手把「可见线 + 隐藏取点线」两条路径合成一条：线端就是落点，`placePacket` 直接在这条线上取点。
  探针实测主体中心 x 收敛到 542（= 箭头尖），淡出 1 → 0 用时 .6s。
- `setWire('done')` 不再把 `stroke-dashoffset` 归零 —— 否则淡出那 .6s 里虚线会在包底下回跳一下；
  实测淡出与 hold 全程停在 `-110`，下一轮起步时才被 `placePacket` 重新写。
- 源端那个同尺寸虚线框**保留**（它表示「这里有一份待发」，不是落点）。
- 窄屏补一条 `@media 860: .sub-hd { flex-wrap: wrap }`：四态 tab 再窄一档就换行。
  （注意：420px 下四个 tab 实际放得下，之前看到的「曲线被裁」是截图 clip 只有 396 宽造成的误判。）
- 验证：13 节 / 21 demo / 7 组 tab / TOC 13、1440 宽 `scrollWidth-innerWidth = 0`、控制台零异常。

## 按规范把 8 个原语页全量对齐

用户：「规范差不多了，根据规范，把所有原语界面改一遍，不符合规范的都改。」

### 最大的一条：字号被 CSS 盖掉了
`stage.css` 里 `.gpu-title{font-size:18px}`、`.dst-badge{font-size:10px}`、`.slot-tx{font-size:15px}`

`drawLegend` **单独补了一条 `font-size`**（它原来完全靠 CSS，删了就退回默认 16px —— 探针抓到 attr=null）。

### GEO 偏差
