## 双排卡 8px 的真相（重要，别再算错）
`assets/prim/motion.js` `CV.cardGeo`：
- `pad1 = (h1 − hdr − 16 − sh)/2` = (170−36−16−46)/2 = 36 → 行顶 72（**减了 16 底边距**）
- `h2 = h1 + sh + rowGap − preWiden` = 170+46+12−25 = 203（preWiden 桌面 25：第二排先吃既有留白）
- `pad2 = (h2 − hdr − 2·sh − rowGap)/2` = (203−36−92−12)/2 = 31.5 → 行顶 67.5 / 125.5（**没减 16**）

即单排「留 16 后居中」、双排「卡内直接居中」，两套口径；差 8 = 16/2。若双排也减 16，pad 变 23.5 → 59.5/117.5，但下排到卡底会剩 39.5，视觉偏上。现状 67.5 是代码真画出来的值，文档照写。
→ 推论：`1.1.5 / 1.2.2 空白区 高度`（118 / 151）本身就是派生量（卡高 − 标题栏 − 16），别再拿它当「行在其中居中」的框。

## 判据（可复用）
参数必须是能被独立赋值的自由度。凡是「A 必然等于 B」或「A 由内容算出来」，A 就不是参数：要么删掉、把关系写进上一级描述，要么换成真正决定它的量（内边距 / 最小宽度 / 卡宽）。

**但用户 2026-11-06 明确否决了对这三处的应用**：既然已经拆成两个量写进表里，它们就是独立参数，改一个时人工评估联动即可；内容定死了尺寸才能定死，改内容本身要审核。→ `1.1.2 宽度 300 / 圆角 上两角 14`、`3.2.1 宽度 36` 全部恢复，`最小宽度` 术语与「宽度随内容」句删除。后续别再拿「是算出来的」当删参数的理由；只对真正没有第二组边界的量（如标题栏宽度=卡宽）才改写进描述。
