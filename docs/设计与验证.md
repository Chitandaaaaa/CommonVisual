# 设计与验证

> 任何项目的两个必要方面：**设计**裁决「什么算对」，**验证**判定「是否算对」，**实现**是两者之间的产物——严格按设计写、通过全部验证。本文件跨项目通用：列出设计与验证各自必须产出哪些东西、每样里面必备哪些章节。项目不涉及的槽位可以跳过，但要在项目规范里显式写「本项目不涉及」。

## 三者关系

设计 → 实现 → 验证：

- 没有设计，实现无对错可言；没有验证，设计只是主张。
- 实现出问题只有两种可能：没按设计写（纪律问题），或设计有缺口（回去补设计）。
- 验证失败同理：实现错了改实现；用例与设计冲突，先改设计——用例是设计的投影。

## 一、设计篇

设计产物从宏观到微观八份。D0–D3 任何项目必有，D4–D7 按项目性质取舍：

| # | 产物 | 管什么 | 必备章节 |
|---|---|---|---|
| D0 | 原则纲领 | 全项目最高原则 | 原则条款；使用方式（下层如何实例化） |
| D1 | 项目总览 | 是什么、交付什么 | 一句话定位；交付物清单；技术栈与硬约束 |
| D2 | 架构设计 | 怎么组织 | 分层与依赖规则；组件清单（职责 + 契约）；扩展流程（加一个新东西要动哪些件）；技术禁区 |
| D3 | 领域口径 | 每个功能域什么算对 | 状态与术语定义；输入输出对照；边界情况 |
| D4 | 过程编排 | 动态过程怎么走（动态系统才要） | 步骤分解；每步口径与文案；时序基线 |
| D5 | 表现规范 | 长什么样（有界面才要） | 组件真值（尺寸 / 颜色 / 动效）；参数基线与修改路径 |
| D6 | 数据事实表 | 数据住哪、谁消费 | 事实清单与归属；消费关系；变更规则 |
| D7 | 变更元规范 | 设计体系自身怎么变 | 基线文件清单；每份的唯一合法改法；伴随义务（回归范围、需同步处） |

每份设计产物只有三个要求：

1. **可判定**——文中每条要求都能判「过 / 不过」。
2. **有出处**——引用的事实写明权威出处文件，不在本文件复述第二份。
3. **单向引用**——只引用更宏观的产物，不引用实现。

## 二、验证篇

验证产物五份：

| # | 产物 | 管什么 | 必备章节 |
|---|---|---|---|
| V1 | 验证策略 | 怎么验证、验到什么程度 | 验证分层（如结构断言 / 量测 / 视觉观感 / 人工确认）；分频（每次改动 / 提交前 / 定期）；通过标准 |
| V2 | 用例清单 | 逐条判过 / 不过 | 编号与分组；每条 = 前置 + 动作 + 期望（可判定）；与设计的对应关系 |
| V3 | 验证工具 | 怎么量真值 | 工具清单与用法；与产物的配对规则；先量真值、后写断言的流程 |
| V4 | 缺陷台账 | 失败怎么记 | 记录格式；生命周期（发现 → 记账 → 修复 → 销账）；失败只记账、不当场散改的纪律 |
| V5 | 回归矩阵 | 改哪里必须验哪里 | 改动位置 → 必跑集合的映射；公共层 / 基线改动的全量回归义务 |

验证只有三个要求：

1. **依据设计**——期望值取自 D 系产物（D3 / D4 / D5 / D6），不取自实现输出。
2. **可判定**——每条用例只有过 / 不过两种结局。
3. **分层省钱**——便宜的断言高频跑，贵的比对低频跑，人工确认只留给机器判不了的部分。

## 三、实现的义务

实现不是独立命题，只有三条义务：

1. **严格按设计写**——实现中不产生设计之外的新决策；发现设计缺口，先回设计补规范，再继续实现。
2. **通过全部验证**——验证不过就是没完成，不存在「功能写完了但验证没过」的完成态。
3. **不反向滋养**——实现中发现真值、口径与设计冲突，走「改设计 → 改实现」；不允许实现悄悄偏离设计后让验证迁就实现。

## 四、三层文档体系

| 层 | 文件 | 生命周期 | 内容 |
|---|---|---|---|
| 一 | 纲领（原则） | 跨项目原样复制，基本不动 | 天条 + 使用方式 |
| 二 | 本文件（方法论） | 跨项目复制，按需裁剪 | 设计篇、验证篇、实现义务 |
| 三 | 项目规范（实例化） | 每个项目自己写 | 槽位挂接到具体文件 + 原则逐条实例化 + 项目特有细则 |

第三层的写法规矩见《纲领》「使用方式」：每条款三选一标注（承纲领·N / 挂槽位 / 本项目特有）。
