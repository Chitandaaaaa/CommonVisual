自动用例 · 机器判对错

6 条，全部已实现
1.1 由全量回归执行；1.2–1.6 是 reducescatter 的考卷，随该页一起跑。
序号用例做什么脚本为什么需要通过标准
1.1 四张截图互不相同 每页在开头（0）、中间（500）、结尾（1000）、窄屏开头（0）各截一张，再两两比字节数。 tools/verify.mjs 画布失效最常见的表现不是报错，是每次跳转都落到同一画面。 四张字节互不相同、输出无「废帧」提示。
1.2 挂载后有 4 张卡 进页面取当前挂载状态，数卡片对象有几个。 tools/probes/reducescatter.mjs 卡片没建出来时，后面所有断言都会读空值而「碰巧通过」。 打印 mount:4 cards cards=4 且 PASS。
1.3 初始态 32 个槽位标签 停在刻度 0，数场景里有几个槽位文字标签。 tools/probes/reducescatter.mjs 4 卡 × 顶排 4 + 接收排 4 = 32，少一个就说明数据块没铺满。 打印 init: 32 slot labels n=32 且 PASS。
1.4 card0 顶排是 A B C D 刻度 0 时取前 4 个标签文字，与 A/B/C/D 逐位比较。 tools/probes/reducescatter.mjs 块数对了但顺序或内容错了，图上看着还是「满的」，只有比对内容能发现。 打印 init: card0 = A B C D ABCD 且 PASS。
1.5 中段计算框会亮起 从刻度 100 扫到 960，每 40 一跳，记录计算框最亮时的不透明度。 tools/probes/reducescatter.mjs 合并段只占总时长一小段，粗采样会整段跨过去，所以必须细扫。 最亮值 > 0.5，且结果里带上出现在哪个刻度。
1.6 终态计算框全隐 跳到刻度 1000，数计算框个数并取最大不透明度。 tools/probes/reducescatter.mjs 计算框该收起来却留着，是最典型的「动画收尾没收干净」。 个数 = 4 且最大不透明度 < 0.05。
边界：这 6 条都不看颜色、间距、观感；没有考卷的 11 页，只有 1.1 一条在用，它的 OK 只说明「这页能跑且四张图不一样」，不代表内容对。

人工用例 · 人眼判读

2 条，全站通用
没有脚本，判据在人眼里；数字能量的部分不放到这里。
序号用例做什么脚本为什么需要通过标准
2.1 桌面四帧观感 看 1.1 出的三张桌面图：颜色对不对、层次清不清楚、节奏舒不舒服。 人眼，无脚本 配色、层级、快慢量不出数字，但一眼就能看出别扭。 每张图能写出一句结论（「正常」或「哪不对」）；写不出说明这张不该截。
2.2 窄屏排版不溢出 看窄屏那张图：有没有横向滚动条、文字有没有被切或叠。 人眼，无脚本 窄屏几何是另一套，桌面正常不代表窄屏装得下。 无横向滚动、无文字截断、卡片不重叠。
边界：人工用例不判数值和像素差——「差几像素」用附注里的探针量，「该不该出现」用第 1 组的断言判。

附：工具与跑法（不属于用例）

跑自动用例
node tools/verify.mjs <页面…> --no-shot 只跑断言不截图；去掉 --no-shot 连 1.1 的四张图一起出。
量真值
node tools/probe.mjs <页面> 0:"<要量的表达式>"，刻度 0 是开头、1000 是结尾；它只报数，不判对错，是写新用例前的尺子。
断言文件
tools/probes/<页面>.mjs，导出 check(pg) 返回 {name, pass, detail} 列表；文件名与页面同名即自动配对，不用改工具。
报错收集
每打开一页挂一份监听（脚本崩溃 + 控制台报错/警告），换页换一份。它是「顺带行为」，不单独算用例。
边界
报错为 0 不等于内容验过；挂载超过 8 秒是静默的，此时头部行 dur=null，OK 属于假通过。
