CommonVisual · 验证方式规范

四种方式逐项拆分，编号固定。本页是验证方式的唯一来源，后续以此为准。
以本页为准 · 改本页需同步 AGENTS.md 一 与 MEMORY.md
四种方式职责不同：只有第 3 种（probes）会判对错，其余三种都不判。先看总览，再看每种的逐项内容。
#方式入口验证什么输出判据
1全量回归
verify.mjs
 node tools/verify.mjs <pages> 报错 / 挂载 / 页面断言 / 截图 pass/fail 表 errors=0 且 probeFail=0
2单点探针
probe.mjs
 node tools/probe.mjs <page> 刻度:"JS" 某一刻的某一个数值 数字 / JSON 不判，自比对
3页面断言
probes/<page>.mjs
 export async function check(pg) 一页的验收口径 {name, pass, detail} 全部 pass
4人工截图
verify 内
 verify（不加 --no-shot） 颜色 / 层次 / 节奏 4 张图 人眼看
一句话分工：`verify` 管「有没有坏」，`probes` 管「对不对」，`probe` 是写 `probes` 前的临时尺子，截图管「好不好看」。
01

全量回归 verify.mjs

一次 Chrome 启动，逐页跑完
作用：体检。回答「页面能不能打开、有没有报错、挂载成功没有、有没有页面断言失败」。
  1. 1.1
    启动本地服务 + 无头 Chrome
    静态 server 绑 127.0.0.1，端口 9100–9189 随机（--port 可固定）；根目录 = 仓库根。Chrome 用系统安装版，参数 --no-proxy-server --force-device-scale-factor=1。
  2. 1.2
    每页打开并等挂载
    新 context 1440×900、DPR 1；goto(waitUntil:'load')；等 window.CV.lastMount.controls 出现，超时 8s（超时静默，不判 fail）；再等 150ms。
  3. 1.3
    收集报错
    监听 pageerror（未捕获异常）+ console 的 error 与 warning。唯一排除项：Failed to load resource（favicon 404 不算错）。
    errors=0 才 OK
  4. 1.4
    加载并执行页面断言
    若存在 tools/probes/<page>.mjs → 动态 import，执行 check(pg)，逐条打印 probe PASS/FAIL；断言内抛错记 probe-throw FAIL。文件不存在则跳过本步（不算失败）。
    本步只管调度，内容在第 03 节
  5. 1.5
    截图集（默认开，可关）
    不加 --no-shot 时，按 --frames（默认 0,500,1000）逐帧：暂停 → seek(v/1000) → 等 900ms（终态 1200ms）→ 截图到 --out（默认 /tmp/cv-verify）。
  6. 1.6
    窄屏截图
    另起 420×820 context → 打开 → 等挂载 → seek(0) → 等 900ms → 存 <page>-narrow.png。
  7. 1.7
    废帧检测
    相邻两张截图字节数完全相同 → 打印告警。仅提示，不 fail
  8. 1.8
    判定与退出码
    OK = errors===0 && probeFail===0；打印 RESULT: OK|ISSUES errors=N probeFail=M；任一页 bad 则进程 exit 1。末尾汇总「N 页，通过 X，有问题 Y」。
  9. 1.9
    不负责
    画得好不好看、动画语义对不对。没有 probes 文件的页面 = 空考卷：它的 OK 只证明「能跑、不报错」。
02

单点探针 probe.mjs

临时量一个数
作用：万用表。回答「此刻这个值是几」。不判对错，量完就走。
  1. 2.1
    命令格式
    node tools/probe.mjs <page> <scrub>:"<JS>" [<scrub>:"<JS>" ...]。冒号左边是刻度 0–1000（0 开头、1000 结尾），右边是一段在页面里执行的 JS。
  2. 2.2
    启动与打开
    server 端口 9200–9289 随机；Chrome 1440×900；打开页面；等 CV.lastMount.controls（8s，静默）。
  3. 2.3
    逐条量数
    暂停播放 → seek(scrub/1000) → 等两帧 requestAnimationFrame（确保布局/绘制已更新）→ new Function('return ('+JS+')')() 求值 → JSON.stringify。
  4. 2.4
    输出
    每行 刻度 值（例：0 32）；求值失败打印 EVAL ERROR ...；末尾若有页面报错打印 PROBLEMS（前 6 条）。
  5. 2.5
    怎么判读
    它不给对错，只有读数。你拿「应然值」和它比：一样就过，不一样就查。EVAL ERROR 或 PROBLEMS 才是异常信号。
    不判对错不进 CI
  6. 2.6
    什么时候用
    改完想知道「现在到底多少」；排查「看起来不对」时先量数再猜；给 probes 找正确值（草稿阶段）。
  7. 2.7
    不负责
    不做多刻度组合断言、不留存记录、不参与定时回归。
03

页面断言 probes/<page>.mjs

唯一会判对错的一种
作用：考卷。把「这一页必须长成什么样」固化成断言，verify 每次自动判。
  1. 3.1
    文件位置
    tools/probes/<page>.mjs，文件名必须与页面同名：reducescatter.html → tools/probes/reducescatter.mjs。
  2. 3.2
    函数契约
    export async function check(pg) → 返回数组 [{ name, pass, detail }]。pg 是 Playwright page；内部用 window.CV.lastMount 取控件与运行时状态。
  3. 3.3
    加载时机
    verify 每页检测同名文件，存在才 import 执行；没有文件就跳过，不影响该页 OK/ISSUES。
  4. 3.4
    断言原则
    只断言「结构上一定成立」的事：数量、终态内容、某段该出现/该消失。像素与配色交给截图。可多次 seek 组合判断；对时间窗口很小的阶段要细扫（现存样例用 step=40），别用固定大步长。
  5. 3.5
    现有断言（reducescatter，5 条）
    R1 挂载 4 张卡：Object.keys(S.cards).length === 4
    R2 初始态 32 个槽位标签（每卡顶排 4 + 接收排 4）
    R3 card0 顶排 = A B C D
    R4 合并段 .calc-wrap 出现过（step=40 细扫，max > 0.5）
    R5 终态 .calc-wrap 全隐（n=4 且 max < 0.05）
  6. 3.6
    异常处理
    check 抛错 → verify 记 probe-throw FAIL，不静默吞掉。
  7. 3.7
    判据
    返回数组里任一条 pass=false → 该页 probeFail > 0 → RESULT 为 ISSUES。
  8. 3.8
    不负责
    观感（颜色、层次、节奏）——那归第 4 种。
04

人工截图

看气色
作用：唯一用眼睛的部分。回答「看起来正不正常」。
  1. 4.1
    触发方式
    verify 不加 --no-shot 时自动产出；输出目录由 --out 指定（默认 /tmp/cv-verify）。
  2. 4.2
    四帧固定
    ① 初始 0@900 ② 飞行中点（scrub=(k+r)/n*1000，段边界不是中点） ③ 终态 1000@1200 ④ 窄屏 0@900 @420×820。
  3. 4.3
    废帧判据
    相邻两帧字节数相同 = 同一画面 → 立刻查（常见原因：端口打错、scrub 没除 1000、seek 被 clamp 成终态）。
  4. 4.4
    只看这些
    颜色对不对、层次清不清楚、节奏舒不舒服、窄屏字幕是否截断/溢出。
    观感
  5. 4.5
    不看这些
    差几像素、数值对错 —— 前者用 probe 量，后者用 probes 判。
  6. 4.6
    纪律
    每张图截之前先写下「这张图要判断什么」；判断不了就别截。「再截一张看看」是最贵的动作。

四者关系

2 · probe
