附：工具与跑法（不属于用例）

每次改完
node tools/verify.mjs <页面…> --no-shot 只跑第 2、3 组，不出图 → 实测 12 页 43 秒（其中 22 次细扫约 6 秒）。改哪页就传哪页，通常 3–5 秒。
提交前 / 定时
去掉 --no-shot，连第 1 组的四张截图一起出（12 页约 3–4 分钟）；每日 09:30 由定时任务跑这一版。
量真值
node tools/probe.mjs <页面> 0:"<要量的表达式>"，刻度 0 是开头、1000 是结尾；它只报数、不判对错，是写新用例前的尺子。
断言写哪
tools/probes/<页面>.mjs，导出 check(pg) 返回 {name, pass, detail}；文件名与页面同名即自动配对。
写断言的速度约束
同一页的 5–6 条断言要共用一次时间轴扫描：先采样一轮（记下每个刻度的读数），再各自比对；不要每条重新 seek 一遍，否则 47 条补完会从 43 秒涨到几分钟。
报错收集
每打开一页挂一份监听（脚本崩溃 + 控制台报错/警告），换页换一份。属顺带行为，不算用例。
边界
报错为 0 不等于内容验过；挂载超过 8 秒是静默的，此时头部行 dur=null，OK 属于假通过。
