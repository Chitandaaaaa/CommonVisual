# 开发纲领

> **任何项目的设计与开发都必须遵守的原则。** 本文件跨项目通用：新项目原样复制，不改条款；每个项目通过自己的「项目规范」（第三层）把条款实例化为可判定规则。

## 天条

**唯一事实，单向依赖，数据行为分离，设计裁决，改动局部。**

一切事实有且只有一个权威出处，其余皆为消费者；一切依赖只允许自上而下；数据只声明「是什么」，行为只声明「怎么做」；「什么算对」由设计裁决、「是否算对」由验证判定；一处改动只落在被改处及其对应设计上。

1. **唯一事实** —— 每类事实（口径、状态、取值、文案……）只有一个权威出处，其余代码与文档只读；禁止第二份拷贝，禁止从实现产物反推事实。
2. **单向依赖** —— 依赖只允许上层消费下层；下层不得感知上层，平级不得互引；共享的唯一合法路径是下沉为公共层。
3. **复用唯一实现** —— 同一能力全项目只有一份实现；写新能力前先查既有实现，没有则先沉淀公共层、再消费。
4. **数据与行为分离** —— 代码只有两种原始单元：数据声明「是什么」，行为声明「怎么做」；数据中不写代码，行为中不藏数据。
5. **设计先于实现** —— 一切「什么算对」由设计裁决；实现与设计冲突时，先改设计、再改实现；实现不得产生设计之外的新决策。
6. **验证依据设计** —— 验证的期望值来自设计，不来自实现自身；拿实现的输出当验证依据即自证，无效。
7. **改动局部化** —— 一次改动只落在被改对象及其对应设计上；需连带修改其他设计文档，说明存在隐藏耦合——先修体系，再做本次改动。
8. **可判定** —— 一切规则与用例必须能判「过 / 不过」；不可判定的表述不成规则，改到能判定为止。

## 使用方式

- 项目规范（第三层）的每一条款必须三选一标注：**承纲领·N**（实例化第 N 条原则）、**挂槽位 Dx/Vx**（填充《设计与验证》某槽位）、**本项目特有**；一个标注都没有的条款删掉。
- 原则不在项目内增删：觉得缺原则或某条不适用，先改本文件（全局生效），再落地到项目。
