名词表

正文只出现这些词 · 定义与时长都在这里

三条规则：颜色、尺寸、坐标不进正文也不进这张表；动作的定义、视觉后果、时长只写在这里，步骤里不再解释；表外的动作词不许出现。

2.1 卡名怎么写

格式 卡形态[-槽号]；同一版面里有好几张同形态的卡时，前面加 r<rank>/。

四槽卡-2四槽卡的第 2 个槽。版面里只有一张四槽卡时这样写就够。gather 的 rank 0—
r1/四槽卡-32×2 版面（四张都是四槽卡）里，rank 1 那张的第 3 个槽。reduce 家族四页—
r2/单槽卡单槽卡只有 1 个槽，不写槽号，用 rank 区分。gather / scatter / broadcast 的右侧三张—
四槽卡整张卡作为主体时（不指某个槽），只写形态名。如「四槽卡 · 长高」—

2.2 物件 · 卡片

名词定义易混点时长
单槽卡卡内 1 个槽，居中，持一段数据。gather / scatter / broadcast 的两侧卡—
四槽卡卡内一排 4 个槽，居中；可能只装了 1 块。能装 4 块不代表装满了—
双排卡上排 4 槽 + 下排 4 槽，卡高多一层。预留之后到收场之前一直是它—
计算态卡双排卡中间再插一层计算框。算完即退回双排卡—
卡体卡片本体。卡宽永远一样，槽多不会变宽。只有高度会变—
标题条 / 角标顶部色带写 rank N；右端小胶囊写 src / dst / 1/4 / 4 段。前两个是角色，后两个是进度—

2.3 物件 · 槽与块

名词定义易混点时长
槽卡内一个方形位置。槽是位置，块是数据。槽可以空着—
空格浅灰底 + 灰虚线框，无字。看得见但没数据—
接收位紫底 + 紫实线框 + 居中 ···。只出现在接收方—
数据块实色底 + 白字母。A 紫 / B 青 / C 绿 / D 橙—
分片块数据块带右下角小下标，表示第几片。all-to-all 用—
Σ 块折进 2 份以上数据的累加块：Σ + 下标列字母 + 上标份数。份数每次相加 +1（all-reduce 是翻倍）—

2.4 物件 · 连线与运动体

名词定义易混点时长
弧线两卡之间的虚线弧，末端一枚小三角箭头。未点亮时是灰的—
直连两卡之间的双向连线，没有箭头。all-to-all 用；同一条线四步都会被点亮—
单体包一个包，内装 1 块数据。gather / scatter / all-gather / reduce-scatter / all-to-all—
整份包一个包，内并排 4 块，表示一整份。broadcast / reduce / all-reduce—
残影包身后两层逐渐缩小的副本，越远越淡。永远在来路上—

收层计算态卡退回双排卡：方框先灭（calcFade 0.35），卡片再缩回（shrinkDur 0.70），两相串行共 1.05s。只剩卡片在缩，数据钉在原地0.70s

时长都是「当前默认值」。它们来自全局规范（飞行 1.5 / 淡出 0.6 / 弹跳 0.55 / 折进 0.42 / 长高 0.75…），齿轮面板一改就整体变。 所以真正的数字必须从时间轴实时算，这份文档里的秒数只是当前默认。 表中变暗 / 复原 / 显形 / 点亮 / 余辉比率一类编排级微过渡有意不入规范（不设全局杆）——定数清单与出处见 visual 13 章「编排级定数清单」。

2.6 衔接 · 一个包的一生 顺序律

一次传递里，同一个包的各相串行推进，一次只有一个主导相。默认链（秒数随参数全局变）：

起飞 → 飞行（1.50）→ 抵达 → 淡出（0.60）→ 落位延迟（0.50）→ 落位 → 弹跳（0.55）→（计算页）计算开始 → 计算中

律条文备注
串行律淡出未完成，不得落位；家族页弹跳未完成不得折进（中间隔着撑开）。并行是分叉，不是风格。与「先逐块撤再收回」「方框早于卡片退场」同一族
落位延迟抵达（含淡出）到起弹之间停 0.50s，全站同默认；时序面板有对应行（choreo 页行名即「落位延迟」）。页面不许把这一拍写死进动词
组件口径弹跳的时长与多块节奏读 visual 08（popDur / seatGap），不许在页面复制第二份曲线或秒数。08 管组件长什么样，本条管它何时上场
面板行语义「落位弹跳」行＝完整弹跳窗口：分量（单颗 popDur，错峰 seatGap）全来自 visual 08，时序面板一根 k 杆整窗缩放，动画逐帧从行分量取秒；落位延迟不折进该行。窗口＝单颗，多块靠错峰依次起跳；防假规范行回归＝2.29

时间与高亮怎么保证对得上

解说区间与动画共用一条时间轴

12.1 时间只算一次

  • 编译时产出每一步的起止与内部段边界；解说行只是在这条轴上按段切分，不手写秒数。
  • 齿轮改倍数、或改播放速度后，时间轴整条重算 → 解说区间跟着重算；文案不动，只刷新区间。
  • 断言：解说最后一行的结束 == 动画总时长；每行结束 ≥ 开始。不等就是偏移对错了，开发期直接报错。

12.2 高亮规则

  • 当前时刻落在 [开始, 结束) 内 → 该行高亮；同刻的几行一起亮，正是「同刻」标记的意义。
  • 结束为空的行（瞬时动作）：从开始时刻起保持高亮 0.15 秒，否则一闪就看不见。
  • 静止行照常高亮 —— 播到静止段，画面无动作、列表也无动作，自洽。
  • 只在「命中行集合」变化时改 class，不逐帧写 DOM；跟随开启时，目标行保持滚动到列表中部附近（±20px 死区内不滚，换行时只挪一行的高度），用户手动滚动后暂停跟随 2 秒。

12.3 名词标准化怎么不跑偏

  • 词表（第 02 章）落成独立文件，解说生成器和面板样式共用同一份，不许各页自己写说法。
  • 生成器只接受词表里的动作词；遇到表外动作直接报错 —— 想加动作必须先补词表。
  • 页面只提供「谁 / 什么 / 去哪」，句子由生成器按固定句式拼：主体 · 动作 + 结果列只放对象。

12.4 解说列是确定好的（禁嵌时间）

  • 时间值只许活在「开始 / 结束」两列——它们随参数重算；解说列与结果列是转写好的文本，不嵌任何时间值、不做任何参数插值（错峰间隔、时长、延迟一律不进文本）。
  • 节奏语义用词表达：同刻说「同时」，分相说「错峰」，落差不写数。
  • 参数改动后解说文本一字不变——文本变了就是把可变值焊死进了文案（「错峰 0.50」在齿轮改成 0.8 后即成假话）。
  • 断言（并入 2.22）：解说 / 结果列无 数字+s、无「错峰 + 数字」字面量。
