# 符合性守则 · 怎么保证代码完全按规范开发

> 本篇回答一个问题：**凭什么说 `src/` 是按 `docs/规范/` 实现的，而不是又长出来的第二套东西？** 四条机制 + 验收清单 + 偏差登记。

---

## 1. 四条保证机制

### 1.1 同构律（结构保证）

`docs/实现/00-实现总纲.md` §3 的模块表就是映射合同：**每个模块头部的注释写明治理文档，每篇规范在①总纲 §2 写明对应模块**。评审任何 PR/改动先问一句：这个改动属于哪篇规范管？答不出来 = 不该改。

### 1.2 键引用（数值保证）

代码中**不允许出现舞台可见的裸值**——秒、像素、色、比率一律 `CV.spec('<键>')`。三类例外（可判定）：

1. **编排秒**：⑥逐页表标注「编排秒」的字面值（说明 0.60、轮歇 0.55、停驻 2s…），在 compile 里以 `ORCH` 常量表集中一处并逐条注释⑥出处；
2. **几何公式的结构常量**：③公式中的 0/1/2（如贝塞尔控制点结构）；
3. **非舞台值**：DOM class 名、事件名、存储键。

扫描法：在 `src/assets/` 里 grep 十六进制色与 `0\.\d+s` 字面量，命中即审（ORCH 表与 spec.js 除外）。

### 1.3 逐字转录（事实保证）

`spec.js` ↔ ④、`facts.js` ↔ ②、`lexicon.js` ↔ ⑤ 是**转录关系**：改值先改文档再转录代码（①§6.2）。转录文件的头部注释必须写「本文件是<篇名>的转录，冲突时以文档为准并回改或登记偏差」。

### 1.4 断言内置 + 冲烟（行为保证）

- **闭合断言**（⑧第 1 类）在 `narrate.js` 内置：行序、结束≥开始、每步末=步末、末步末=总时长、表外词抛错。编译期即失败，不靠人眼。
- **冲烟**（`src/dev/verify.mjs`）：8 页无头加载零报错、总时长>0 且各页 step 数与⑥逐页表一致。
- 时长对账：compile 输出各页总时长，与⑥公式链手算值对照（见 §3 偏差 D2 的对照表）。

## 4. 对账基准声明

`src/` 的对账基准是 `docs/规范/`，**不是旧 `assets/` 的行为**。旧站点与本实现允许在快照值级偏差（见 D2）；凡规范条款（顺序律、词表、状态机、参数键）一律不允许偏差。
