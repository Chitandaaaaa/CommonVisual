## 4. 批次明细

### #1 RS 折进目标列 bug（缺陷 · 必修）

- **症状**（用户原话）：RS 逐动作解说 3.12（第 3 步第 1 轮第 12 行「2 段·折进」），
  rank2 本该把 C 折进自己上排 C 列，实际 C 块飞到 A 的位置再去融合。
- **根因**（已定位）：`split.js` ghosts 折进的 fuse 目标写成本卡接收序号：
  `S.chips[gh.r][gh.idx]`、`rsChipState(gh.idx, …)`。rank2/3 第 1 轮收列 2、3（idx=0、1），
  idx≠seg，于是目标列错位、换 Σ 颜色也错。r0/r1 恰好 idx==seg，所以只有 rank2/3 可见。
- **修复**：fuse 目标与身份全部改用全局列号 `gh.seg`（chp、resetTo/to、seat 脉冲目标、
  seen 键）；**错峰节奏保留按本卡接收顺序**（mergeE 的 idx 不动，r2 是 C 先 D 后，视觉自然）。
- **验收**：新探针——RS 第 1 轮折进中段，rank2 折进飞行块 x ≈ 列 2 中心、rank3 ≈ 列 3；
  观感帧 RS r1 折进中点。

### #2 RS「卡片收窄」真收窄（行为 · 本批最大子项）

- **现状**：slim 行（blockDur）只做 `recvAlpha` 淡出第 2 轮用不上的接收格，卡宽从不变化——
  名为收窄、实不收窄。
- **目标态**：第 1 轮计算结束（down1）后，每卡**收窄到保留列**：
  r0/r1 保留列 0、1（左半），r2/r3 保留列 2、3（右半）；卡宽 4 列 → 2 列，
  r0/r1 左缘不动缩右缘、r2/r3 右缘不动缩左缘；徽章随卡框；连线每帧按卡框重算（现成）；
  第 2 轮全程窄卡；**收场复原 4 列全宽**。上排仍持有的段、下排保留接收格在窄卡内按全局列位对齐。
- **改动**：split.js overlay 的逐帧卡几何（R[r] 现在全宽常量）加收窄插值窗口
  （AT.r2open 起 BLOCKD 时长）；卡内槽位坐标从「全宽居中」改为「全局列 → 卡内偏移」；
  收场（rowClose）宽度回插值；手写稿/解说第 4 步行文改「卡片收窄到保留列」。
- **风险**：槽位坐标重排牵动 ghost/recvRow/chips 三组坐标——探针断言
  （slim 完成后卡宽 = 2 列宽、r0/r1 左缘 = 原左缘、r2/r3 右缘 = 原右缘）+ 观感双守。
- **依赖**：#5 完成后做（共用卡几何函数）。

### #3 完成 / 收场拆两步（行为）

- **齿轮**：有收场三页 = …计算结束 → **收场**（复原动画一行）→ **完成**（停驻一行）。

  归入第 2 轮组，与齿轮对齐）。
- **口径**：2.7 总表「完成（收场）」拆为「收场」（三页；方框先没→撤第二排→收回单排）与

- **验收**：三页齿轮行序断言 + 观感（收场动画与停驻分离可见）。
