附：工具与跑法（不属于用例）

首次使用
仓库根目录 npm i（装 playwright-core）。浏览器默认自动探测 Chrome / Edge 常规安装位；特殊位置用环境变量 CV_CHROME 指定，playwright-core 位置用 CV_PLAYWRIGHT_CORE 指定。工具不写死任何一台机器的路径。
每次改完
node tools/verify.mjs <页面…> --no-shot 跑第 2、3、4 组，不出图 → 11 页实测约 2 分钟（含播放回绕 / 齿轮重载 / 窄屏切换这些交互用例）。改哪页就传哪页；docs 规范页带路径：verify docs/prepost.html。
提交前 / 定时
去掉 --no-shot，连第 1 组的四张截图一起出（11 页约 3–4 分钟）；每日 09:30 由定时任务跑这一版。
量真值
node tools/probe.mjs <页面> 0:"<要量的表达式>"，刻度 0 是开头、1000 是结尾；只报数、不判对错，是写新用例前的尺子。
断言写哪
tools/probes/<页面>.mjs，导出 check(pg) 返回 {name, pass, detail}；文件名与页面同名即自动配对。
写断言的速度约束
同一页的断言必须共用一次时间轴扫描：先采样一轮记下各刻度读数，再各自比对；不要每条重新 seek，否则全部用例补完会从 43 秒涨到几分钟。
报错收集
每打开一页挂一份监听（脚本崩溃 + 控制台报错/警告），换页换一份。属顺带行为，不算用例。
边界
报错为 0 不等于内容验过；挂载超过 8 秒是静默的，此时头部行 dur=null，属假通过 —— 2.1 就是为抓它而设。
