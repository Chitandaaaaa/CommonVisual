## 二、设计侧条款

### D1 以规范清单为准（承纲领·5 设计先于实现；挂槽位 D7）

- 全站一切「什么算对」由 `docs/specs.html` 01 章的在册清单裁决：语义看 #3/#7、算法看 #4/#8、步骤文案看 #5、视觉真值看 #6、过/不过由 #11 判。
- 写任何内容前先在清单里找到对应规范，从它出发；清单没覆盖的，先入册成规范、再动手实现。
- 规范与实现冲突时，改规范是第一步，改代码是第二步。

### D2 遵循关系图依赖（承纲领·2 单向依赖；挂槽位 D2）

- 新增任何设计内容前，先在 `specs.html` 02 章关系图上定位它在体系中的位置，遵循图中既定的依赖与对应关系；不新增旁路，不随意改变既有依赖。

## 三、架构侧条款

### A1 分层单向依赖（承纲领·2 单向依赖）

- 页面 HTML 只包含资源引用和 `CV.boot('<id>')`。
- `scenes/*.js` 只引用 registry / rounds / engine / parts / prim / theme。
- engine / parts / prim / theme 只引用更底层的公共层，不引用 scenes 与页面。
- `docs/` 规范页只引用 engine / parts / theme，与业务代码（scenes / registry / rounds）互不依赖，两条线各自向下共享组件。

### A2 薄壳与纯数据（承纲领·4 数据与行为分离）

- 页面壳只承担「加载即启动」：内容、文案、时序全部写在 scenes 剧本里。
- 剧本保持纯数据：整份对象能过 `JSON.stringify` 不失真（无函数、无 undefined、无 DOM 引用）。

### A3 时间唯一所有者（承纲领·1 唯一事实）

- 时间轴编译一次，之后只读；播放、seek、循环都是对同一个 t 的不同推进方式。
- 场景状态的每次变化都由引擎按 t 推导得出，组件只产出描述（关键帧、参数），不自持时钟。

### A4 零构建运行（本项目特有）

- 所有脚本用普通 script + defer 加载，经 `window.CV` 命名空间暴露（约定数据位如 `CV_PARAM_DEFAULTS` 之外不再设全局）。
- 运行环境按 file:// 直开对待：路径全部用相对引用，能力用所有浏览器原生支持的写法。

### A5 组件一致性（承纲领·3 复用唯一实现）

- 写新能力前先查组件库，已有就直接复用。
- 组件库没有的能力，先落公共层、再在各消费点使用；同一能力全站只此一份实现。

### A6 取值令牌化（承纲领·4 数据与行为分离、1 唯一事实）

- 多页共享、#6 视觉规范在册的尺寸/颜色/耗时，一律引用 theme 令牌或 defaults.js。
- 页面私有的编排时长（衔接、停顿）集中声明在 scene 顶部常量区。
- scrub（0–1000）与 seek（0–1）的换算统一经页面 `getCh()` 完成。

### A7 动公共层必全量回归（承纲领·7 改动局部化；挂槽位 V5）

- 改动落在公共层（engine / parts / prim / theme / boot / registry / defaults.js / pages-base.js）时，当次对 8 原语页 + index + docs/prepost.html + docs/visual.html + docs/steps.html 全部跑 verify，全绿后收尾。
- 几何变了先回 #6 / #5 规范正文对口径，再动代码。

### A8 数据与行为的单元（承纲领·4 数据与行为分离）

- 数据的最小单元是**条目**：一条自足的声明，不含代码，可整体序列化。
- 行为的最小单元是**模块**：有名字、有输入输出契约、可整体复用与替换（载体形态随项目而异——函数、类、组件皆可）；模块内部函数不外露。
- 数据里出现的逻辑应改写为行为，行为里写死的取值应提为数据。
